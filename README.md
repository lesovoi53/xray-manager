## 🎯 О проекте

**X-Manager** превращает чистый Linux VPS в защищённый, высокопроизводительный сетевой шлюз. Проект написан на чистом Bash и стандартной библиотеке Python 3 без сторонних фреймворков и лишних зависимостей.

Проект разработан для работы с **ЛЮБЫМ ядром Xray** (standalone Xray-core, системный сервис `xray.service` или произвольная конфигурация Xray), а также поддерживает полностью автономную работу без Xray с прямым выходом в сеть (Direct WAN).

Скрипт берёт на себя всю рутину системного администратора:
* Устанавливает и настраивает все передовые протоколы обхода блокировок.
* Интегрирует протоколы с маршрутизацией ядра **Xray** через 3 универсальных локальных шлюза (`Mixed Gateway`, `TPROXY Gateway`, `REDIRECT Gateway`).
* Обеспечивает полный перехват трафика **TCP + UDP** для Snell v5 и протокол `mixed` с UDP для Mieru.
* Включает встроенный высокоскоростной **сервер подписок TUNA** с поддержкой множества узлов каждого протокола, кастомных имён подключений, раздачей Base64-ссылок и защитой токенами SHA-256.
* Тонко оптимизирует ядро Linux под аппаратные характеристики сервера (RAM, CPU, сеть).
* Защищает сервер встроенным файрволом портов и сервисом **Fail2ban** с автоопределением кастомных портов SSH.
* Предоставляет интерактивный терминальный интерфейс с быстрыми алиасами для каждого компонента (`x-snell`, `x-mieru`, `x-wdtt`, `x-csqtt`, `x-openflux`, `x-dns`, `x-sub`, `x-ssl`, `x-fw`, `x-opt`).

## 🌐 Универсальные шлюзы ядра Xray (Xray Inbounds)

X-Manager организует взаимодействие всех прокси-протоколов с ядром **Xray** через 3 специализированных локальных шлюза (inbounds), изолированных на интерфейсе `127.0.0.1`:

| Шлюз в ядре Xray | Прослушивание | Протокол | Назначение |
| :--- | :--- | :--- | :--- |
| **`Mixed Gateway`** | `127.0.0.1:10808` | `mixed` (SOCKS5/HTTP, UDP on, noauth) | Точка входа для **Mieru (mita)**, **CottenDNS** и **MasterDnsVPN**. Поддерживает TCP и UDP без авторизации. |
| **`TPROXY Gateway`** | `127.0.0.1:12345` | `dokodemo-door` (TCP/UDP, tproxy) | Прозрачный перехват трафика **WDTT (qwdtt)** с sniff-детекцией HTTP/TLS/QUIC и направлением в балансировщики или аутбаунды Xray. |
| **`REDIRECT Gateway`** | `127.0.0.1:12346` | `dokodemo-door` (TCP/UDP, followRedirect) | Полный перехват исходящего трафика **Snell v5** (TCP + UDP) и **OpenFlux (L4)** в ядро Xray с защитой от зацикливания пакетов и исключением подсетей облачных платформ (Яндекс, Mail.ru, VK). |

> Все три шлюза слушают только `127.0.0.1` и защищены правилом `iptables -A INPUT -p tcp/udp ! -i lo -j DROP` — доступ из внешней сети полностью закрыт.

## 🧩 Возможности и стек протоколов

### 1. ⚡ Snell v5.0.1 (Гибридный режим 0-RTT, TCP + UDP перехват)
* **Двойной режим работы:**
  * На **Android / Windows** (**NekoBox+**, **sing-box**) работает на максимальной скорости по чистому TCP с поддержкой мультиплексирования соединений (**Connection Reuse**) и **TCP Fast Open (TFO)**.
  * На устройствах **Apple** (**Surge**, **Shadowrocket**, **Loon**) автоматически задействует быстрый протокол **QUIC 0-RTT** поверх UDP.
* **Полный перехват в ядро Xray (TCP + UDP):** исходящий трафик Snell перенаправляется в `REDIRECT Gateway` (:12346) как для TCP, так и для UDP, а ответы клиентам на собственный порт (QUIC) защищены от зацикливания.
* **Маскировка:** встроенный HTTP-обфускатор для обхода глубокого анализа пакетов (DPI).
* **Готовые ссылки:** автогенерация ссылок `snell://` с параметрами `&reuse=true&tfo=true`, QR-кодов и конфигураций для Surge.

### 2. 🚀 Mieru (mita v3.37+) с защитой от ТСПУ
* Протокол с маскировкой под случайный шум, устойчивый к активному зондированию цензоров.
* **Режимы низкой энтропии (Low-Entropy):** пресеты `LOW_ENTROPY_MODE_32`, `40`, `48`, `56`.
* **Вращение маски (Mask Rotation):** `LOW_ENTROPY_MASK_ROTATE_RIGHT_7` и конструктор пользовательских параметров.
* **Маршрутизация через Xray:** egress направляется в `Mixed Gateway` (:10808) с протоколом `mixed` и включенным UDP.
* **Интерактивный конструктор профилей** в меню Mieru с автогенерацией ссылок `mierus://` и QR-кодов.

### 3. 🛡️ WDTT / qwdtt (WireGuard over WebSocket / TURN)
* Высокоскоростной туннель для стабильного транспорта в условиях жёстких сетевых ограничений.
* **Два режима выхода:** прозрачный перехват через **Xray Core (TPROXY Gateway :12345)** или **Прямой выход (Direct WAN)** с NAT Masquerade.
* Мониторинг в реальном времени: счётчики байт (Rx/Tx), статус воркеров ядра, число активных клиентов.

### 4. 📋 Сервер подписок TUNA (`tuna-subscriptions`)
* Автономный высокопроизводительный демон на стандартной библиотеке Python 3 (zero external dependencies).
* **База данных SQLite в режиме WAL:** надёжная работа при параллельных запросах клиентов.
* **Криптографическая безопасность:** Bearer-токены хранятся в виде SHA-256 хешей, поддержка ротации токенов.
* **Поддержка нескольких узлов на протокол:** возможность добавить пользователю 2, 3, 4 и более ссылок любого типа (Snell, Mieru, WDTT, CSQTT, DNS, VLESS и др.).
* **Индивидуальное именование подключений:** задание кастомного имени сервера (`#name`) для каждой ссылки, включая формат `csqtt://pass@ip:port#name`.
* **Гарантированное удаление пользователей:** многоуровневое удаление через REST API и прямой SQLite fallback коммит.
* **Поддержка HTTP-кэширования (ETag / 304 Not Modified):** экономит трафик клиентов и ресурсы сервера.
* **Выдача подписок:** по адресу `/sub/<token>` сервер отдаёт Base64-список конфигураций, совместимый с любыми клиентами (NekoBox, sing-box, v2rayN, Streisand, FoXray, Happ).

### 5. 🔒 CSQTT (VPN Server)
* Высокопроизводительный UDP-туннель на базе современного протокола WireTurn.
* **Изоляция служебных интерфейсов:** порт веб-управления закрывается от сканеров из внешней сети (`DROP ! -i lo`).
* Возможность безопасного входа через зашифрованный SSH-туннель:
  ```bash
  ssh -N -L 37002:127.0.0.1:37002 root@IP_СЕРВЕРА -p SSH_ПОРТ
  ```

### 6. 📡 OpenFlux (Мультиплексный L4-туннель через Яндекс и Mail.ru Документы)
* **8 независимых параллельных каналов (`openflux@1` ... `openflux@8`):** каждый канал работает как отдельный изолированный сервис systemd со своим конфигурационным файлом (`/etc/openflux/instances/%i.env`).
* **Одновременная работа с разными транспортами (Multi-Transport):** разные каналы могут **одновременно и параллельно** использовать различные транспорты и облачные платформы:
  * `vyandex` — Яндекс Волга (современный редактор документов Яндекс 360 / Яндекс.Диск)
  * `mailru` — Mail.ru Документы (`docs.datacloudmail.ru` / Облако Mail.ru)
  * `yandex` — Яндекс OnlyOffice (классический редактор)
* **Автоматическое определение транспорта:** при вводе ссылки в меню диспетчер автоматически распознаёт платформу (`disk.yandex.ru` / `docs.yandex.ru` ➔ `vyandex`, `cloud.mail.ru` / `mail.ru/public` ➔ `mailru`).
* **Пользовательский стек gVisor L4:** надёжный и стабильный userspace-прокси без риска падения ядра.
* **Перехват в ядро Xray (:12346 REDIRECT):** исходящий трафик OpenFlux направляется в ядро Xray с автоматическим исключением IP-пулов Яндекса (`77.88.0.0/18`, `87.250.250.0/24`) и Mail.ru/VK (`94.100.180.0/24`, `217.69.139.0/24`) для защиты от зацикливания.
* **Сквозное шифрование AES-256-GCM:** возможность включить дополнительный криптографический слой защиты поверх TLS.

### 7. 🌐 DNS-Туннели (CottenDNS / MasterDnsVPN)
* Туннелирование трафика через DNS-запросы (порт `:53 UDP/TCP`) для обхода тотальных белых списков.
* **CottenDNS (WhiteDNS Engine) и MasterDnsVPN:** переключение в 1 клик без конфликта портов.
* **3 профиля `stormdns://`:** «Жёсткая цензура» (x4 дублирование), «Стандартный» (x2) и «Мобильный / Скоростной» (x1).

### 8. 🛡️ Центр управления файрволом портов (`x-fw`)
* **Включение и выключение протоколов без остановки служб:** моментальное открытие или закрытие входящего порта любого протокола (Mieru, Snell, WDTT, CSQTT, DNS) через правила iptables.
* **Режим экстренного локдауна (Emergency Lockdown):** мгновенная блокировка всех прокси-портов с сохранением доступа по SSH.
* **Синхронизация портов:** автоматическое открытие актуальных портов и очистка устаревших правил при смене портов или перезапуске.

### 9. 🔒 Управление SSL-сертификатами (`x-ssl`)
* Выпуск и продление бесплатных SSL-сертификатов Let's Encrypt через `acme.sh`:
  * **Cloudflare DNS-01:** выпуск Wildcard-сертификатов (`*.domain.com`).
  * **HTTP-01 Standalone:** автоматический выпуск по порту `:80`.
* **Мультипутевой детектор:** автоматический поиск и привязка существующих сертификатов из `/root/cert/`, `/etc/letsencrypt/`, `/etc/ssl/`.

### 10. ⚙️ Системная оптимизация и безопасность (`x-opt`)
* **🌐 Смена системного DNS с замером пинга в реальном времени:**
  * 16 провайдеров (Yandex, Cloudflare, Google, Quad9, Control D, AdGuard, OpenDNS и др.) с параллельным замером задержки в мс.
  * Фиксация в `/etc/resolv.conf`, `systemd-resolved` и `dhclient.conf`.
* **🚀 Включение BBR и адаптивный тюнинг буферов под RAM:**
  * Автоматический расчёт сетевых буферов под точный объём оперативной памяти (до 1.5 ГБ, 2–4 ГБ, > 4 ГБ).
  * Включение `tcp_fastopen = 3`, `tcp_tw_reuse = 1`, `tcp_fin_timeout = 20`, `tcp_slow_start_after_idle = 0`.
* **💾 Управление файлом подкачки SWAP:**
  * Создание/удаление swap-файла на **2 ГБ** или **4 ГБ** с тюнингом `vm.swappiness = 10` и `vm.vfs_cache_pressure = 50`.
* **🛡️ Защита Fail2ban:**
  * Автоопределение нестандартного SSH-порта и изолированный jail.
  * Просмотр банов, ручной бан/разбан, настройка времени бана.

## 📱 Клиентские приложения и импорт

### 1. NekoBox+ (Android / Windows)
* **Подписки TUNA:** перейдите в `Группы` ➔ `Добавить группу` ➔ вставьте ссылку формата `http://IP:22217/sub/ВАШ_ТОКЕН` ➔ все протоколы обновятся автоматически.
* **Mieru:** импорт через `mierus://` или QR-код из меню `x-mieru`.
* **Snell v5:** ссылка генерируется с параметрами `&reuse=true&tfo=true` для максимальной производительности.

### 2. Surge / Shadowrocket / Loon (iOS / macOS)
* В меню `x-snell` генерируется готовая строка для Surge:
  ```ini
  Snell-v5 = snell, IP_СЕРВЕРА, ПОРТ, psk=ВАШ_PSK, version=5, reuse=true, tfo=true, udp-relay=true
  ```
* Поддержка **QUIC 0-RTT** поверх UDP на устройствах Apple.

### 3. Karing / sing-box / Happ / v2rayN
* Прямая поддержка ссылок из подписок TUNA и нативных протоколов.

## 🔒 Безопасность и архитектура портов

```
[Интернет / Входящие подключения клиентов]
        │
        ├── :1488 (Snell v5)       ──► [Snell Server] ──(TCP+UDP)──┐
        ├── :2020-2030 (Mieru)     ──► [mita core]    ──(SOCKS5)───┤
        ├── :56000 (WDTT UDP)      ──► [wdtt-tproxy]  ──(TPROXY)───┼──► [Xray Core]
        ├── :53 (CottenDNS/Master) ──► [DNS Tunnel]   ──(SOCKS5)───┤     │
        ├── :22217 (TUNA Sub API)  ──► [tuna-sub-server] (127.0.0.1)│     • Mixed Gateway    :10808 (127.0.0.1 🔒)
        └── :SSH (SSH + Fail2ban)  ──► [sshd]                      │     • TPROXY Gateway   :12345 (127.0.0.1 🔒)
                                                                   │     • REDIRECT Gateway :12346 (127.0.0.1 🔒)
[Изолированный сервис CSQTT]                                       │
  :37002 (TCP) ──► Доступен ТОЛЬКО через локальный SSH-туннель ─────┘
```

* **Шлюзы ядра Xray** (`Mixed Gateway` :10808, `TPROXY Gateway` :12345, `REDIRECT Gateway` :12346) изолированы на `127.0.0.1` (`DROP ! -i lo`).
* **Сервер подписок TUNA** слушает локальный интерфейс (`127.0.0.1:22217`) или подключается через внешний reverse proxy / прямой порт с обязательной Bearer-авторизацией по токенам.
* **Защита Fail2ban** предотвращает атаки перебора паролей на реальном SSH-порту.
