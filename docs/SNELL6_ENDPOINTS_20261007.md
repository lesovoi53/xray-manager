# Snell v5 / Snell v6

Обновлено 7 октября 2026. На сервере работает только одна выбранная версия:
Snell v5 либо один сохранённый endpoint Snell v6. Остальные настройки сохраняются.
Общий PSK допускает одновременные подключения. Управление пользователями Snell
не реализуется. Пользователи TUNA остаются получателями подписок.

Snell v6 поддерживает `default`, `unshaped`, `unsafe-raw`; обычный UDP relay
поддерживается. QUIC Proxy исключён. В `unsafe-raw` нет шифрования и проверки
PSK: этот режим требует явного выбора и соответствующего предупреждения.

## Установка и команды

Основной установщик доставляет `scripts/snell6-endpoints.py` вместе с
`snell-subscriptions.py`, `snell-switch.py` и `service-control.py` в
`/usr/local/share/x-manager/scripts/`, а `systemd/snell6@.service` — в
`/etc/systemd/system/`. Доставка этих файлов не создаёт подключений и не
скачивает новое ядро. Интерфейс меню:

```sh
python3 /usr/local/share/x-manager/scripts/snell6-endpoints.py menu
```

CLI принимает `create`, `set`, `update`, `publish`, `uri`, `status`; слот
задаётся как `--slot 1` … `--slot 8`. `create` и `set` читают JSON из stdin.
Для нового подключения нужен `server_host`; PSK и стабильный `endpoint_id`
создаются один раз, свободный TCP-порт выбирается автоматически. Существующие
порты сохраняются. Для новых портов запрещены 443/8443 и привилегированный
диапазон; учитываются активные TCP/UDP listeners, другие v6 endpoints и порт v5.

Поля JSON: `server_host`, `name`, `port`, `psk`, `listen`, `mode`, `routing`,
`socks_port`, `probe_url`, `firewall_open`. Для `listen` допустимы только
`0.0.0.0` и `127.0.0.1`. `routing` по умолчанию `xray`: единственный SOCKS5
outbound через `127.0.0.1`, без direct fallback. Порт берётся из сохранённого
`XRAY_SOCKS_PORT`, иначе 10808. `direct` выбирается явно.

`publish --slot N --user ID` добавляет URI только выбранному существующему
пользователю TUNA. Повтор не создаёт дубликат и не меняет revision. Перед
публикацией выполняется настоящий Snell→HTTPS запрос с проверкой TLS.
`probe_url` по умолчанию `https://example.com/`; для управляемой проверки
следует указать свой доступный HTTPS URL с ответом HTTP 2xx. Недоступность
этого URL считается неуспешной проверкой, а не доказательством сбоя Snell.
`uri` печатает ключ в составе ссылки — это явный экспорт, не диагностика.

Активация выполняется через переключатель. Он проверяет выбранную конфигурацию,
сохраняет резервную копию, выключает остальные Snell-службы, проверяет новый
маршрут и фиксирует выбор только после успешной проверки. При обычной ошибке
возвращает предыдущее состояние. Прямое включение невыбранной версии через
общий контроллер запрещено. Для возвращения v5 используется
`snell-switch.py switch --version 5`.

Примеры:

```sh
python3 /usr/local/share/x-manager/scripts/service-control.py off snell6@1
python3 /usr/local/share/x-manager/scripts/snell-switch.py switch --version 6 --slot 1
```

`set`/`update` сохраняют остановленное, disabled, masked и постоянно
выключенное состояние. Изменение имени не перезапускает процесс.

## Файлы, ядро и восстановление

- Идентичность: `/etc/snell6/endpoints/N/endpoint.json`, root:root 0600.
- Конфигурация: `/etc/snell6/endpoints/N/config.json`, root:snell6 0640.
- Отдельный непривилегированный пользователь и группа `snell6`.
- `core` — ссылка на неизменяемый каталог бинарника
  `/usr/local/lib/x-manager/snell6/<SHA-256>/sing-box`.
- Закрытые резервные копии: `/var/backups/x-manager-snell6-*`.

Закреплён [sing-box-extended 1.14.1-extended-2.7.2](https://github.com/shtorm-7/sing-box-extended/releases/tag/v1.14.1-extended-2.7.2),
артефакт `sing-box-1.14.1-extended-2.7.2-linux-amd64-purego.tar.gz`.
SHA-256 архива: `e4606cc7e3ee19885b5c16ad4ec8e28c8b3bacbc31949f93018cd5c77883b28b`.
SHA-256 бинарника: `187965235a83a462aa10291cfab561d0caed2fde90a608e6899b17aed9e01ea8`.
`--core-source PATH` использует локальный файл с тем же обязательным digest.
Архив загружается как `snell6-amd64.tar.gz` из нашего выпуска, с проверкой
`components.json` и закреплённого SHA-256. До публикации нового выпуска доступен
локальный проверенный артефакт. Плавающий `latest` и произвольная замена версии
не используются.

До изменения endpoint проверяются digest, ELF amd64 и native `check -c`.
После запуска — активность службы и реальный аутентифицированный Snell→HTTPS
запрос через выбранный outbound. Для Xray отдельно проверяется поддержка
SOCKS5 no-auth и UDP ASSOCIATE. Эта проверка UDP ASSOCIATE не равнозначна
передаче настоящего UDP-пакета до удалённого адресата.

Файлы и состояние службы восстанавливаются при обычной ошибке операции.
Изменения существующих URI выполняются через прежний генератор в одной
`BEGIN IMMEDIATE` транзакции SQLite; при ошибке вызывается rollback.
Старая целая база поверх параллельных пользовательских данных не копируется.
Меняются только привязанные URI и их точные копии в группах, сохраняются
пользовательские alias, ID, токены, v5 и внешние ссылки.

Firewall использует только отдельное TCP INPUT-правило с комментарием
`XM_SNELL6_<endpoint_id>`. Привилегированный `ExecStartPre` восстанавливает его
при загрузке согласно `firewall_open`; полный firewall не сохраняется и не
очищается. Постоянное выключение/ручной stop блокируют сам запуск и hook.
Если правило было удалено вручную, `update` сначала сохраняет закрытое
состояние. Изменение транспорта при конфликте сохранённой/фактической
firewall-политики отклоняется до изменений.

Для основного installer snapshot нужны `/etc/snell6`,
`/usr/local/lib/x-manager/snell6`, `snell6@.service`, состояния слотов 1…8 и
их собственные lifecycle/watchdog drop-ins. Общая транзакция установщика
остаётся ответственностью основного установщика.

## Подписки и настройки

Меню показывает Snell v5 и Snell v6. У v6 доступны имя, адрес выдачи, порт,
общий PSK, режим, адрес прослушивания, Xray/Direct, SOCKS-порт и доступ через
firewall. Создание сохраняет endpoint; активация — отдельное действие.

В выдаче TUNA локальные ссылки фильтруются по точным сохранённым привязкам
генератора. Выбранный v5 выдаётся с клиентским `version=4`, v6 — `version=6`
и `udp-relay=true`. Иностранные ссылки не удаляются. Неактивные локальные
ссылки остаются в базе; переключение меняет выдачу и ETag, а не реквизиты.
Непривязанные вручную добавленные ссылки считаются внешними: нельзя безопасно
определять владение только по IP. Для старых локальных ссылок используйте
существующую синхронизацию локального Snell, создающую точную привязку.

Редактор ссылок v5 сохраняет ссылки v6 при добавлении, замене и очистке.
Группы, потерявшие минимальный состав или выбранный профиль маршрутизации,
не выдаются в текущем ответе; сохранённые группы не изменяются.

## Резервные копии и откат

Выбор хранится в `/etc/x-manager/snell-active.json` без секретов. Переключатель
сохраняет закрытые снимки в `/var/backups/x-manager-snell-switch/`.
При ошибке переключения состояние восстанавливается автоматически; если
восстановление не удалось, команда завершится с явной ошибкой.
Основной выпуск обновляйте через штатное обслуживание; для отката выпуска
используйте его пункт восстановления резервной копии. Не копируйте старую
базу поверх новых пользовательских изменений.

## Подтверждённая граница

Режимы проверены настоящим закреплённым ядром: 48 проверок HTTPS/UDP,
совпадения режимов, общего ключа и повторного использования соединений.
Переключатель прошёл 10 сценариев с systemd и настоящим Snell v5;
662 замера не обнаружили одновременных слушателей. HTTP obfs v5 проверена.
TLS obfs этим native v5 не поддерживается: проверено отклонение с откатом,
без изменения конфигурации на другой режим.

На разрешённом тестовом VPS 109.237.98.220 проверены переключения v5/v6,
повторная активация без перезапуска, HTTPS через настроенный Xray, три клиента
с общим ключом и реальный UDP DNS-запрос. Настройки и база подписок сохранены;
после проверки активен v5. Это не проверка Android-клиента.

Не проверены внезапное отключение питания посреди транзакции, ENOSPC,
обновление между разными версиями ядра и длительная нагрузка. Новые изменения
ещё не опубликованы; публикация выполняется после пользовательской приёмки.
