# Подготовка генератора подписок Snell v6

5 октября 2026. Локальная реализация внутреннего API генерации и синхронизации. **17/17 тестов прошли в Debian 13, 0,482 с**, включая 11 прежних проверок v5 и 6 новых сценариев v6. `git diff --check` прошёл.

## Что изменено

`scripts/snell-subscriptions.py`: функция `uri()` принимает модель v6 с `version=6`, `mode`, `port`, `psk`, `name`. По умолчанию mode=default. Без version сохраняется прежнее поведение v5. V6 не получает obfs-поля; предыдущая v5-ссылка не преобразуется в v6 неявно.

Проверяются режим, обязательные данные, управляющие символы, дубли параметров, несовместимые obfs, network/udp-relay и неподдержанный QUIC Proxy. URI правильно кодирует пробелы, кириллицу, специальные символы ключа и IPv6-адрес. Существующие клиентские reuse/tfo/udp-relay/network/userkey сохраняются; управление серверными userkey здесь не добавлено. Режимы unshaped/unsafe-raw поддержаны только как значения модели генератора, их серверная установка не реализована.

Для `synchronize()` v6 обязателен стабильный `endpoint_id`. Привязки хранятся отдельно в `x_manager_snell_endpoint_links` с составным ключом `(endpoint_id,user_id,uri)`; прежняя таблица v5 не меняется. V6 допускает только явную привязку точной сгенерированной ссылки, без автоматического поиска по адресу. Одну ссылку пользователя нельзя привязать к двум endpoint ID.

Обновляются только точные привязанные снимки URI выбранного endpoint и их точные копии в группах. ID профилей и групп, пользовательские имена профилей, токены, другие протоколы, v5 и внешние ссылки сохраняются. Повторный запуск без изменений не повышает revision. Конфликт дубликатов отменяет транзакцию. Как и прежде, **транзакцией владеет вызывающая сторона**: использовать `with db:` либо существующий транзакционный helper, не вызывать запись вне контролируемой транзакции.

## Проверки

Новые тесты в `tests/test_snell_subscriptions.py` проверяют:

1. Кодирование ключа/имени/IPv6, сохранение клиентских флагов и пользовательского alias.
2. Отказ для несовместимых параметров и неявной миграции v5 → v6.
3. Синхронизацию v6 в базе вместе с привязанным v5 и внешней ссылкой, сохранение групп/токенов/другого протокола, отсутствие изменений при повторе.
4. Обязательный endpoint ID и запрет неявного adoption.
5. Изоляцию двух v6 endpoints, запрет двойной привязки одной ссылки.
6. Полный откат изменений пользователя при конфликте дубликатов.

Использовались временные SQLite и файлы, синтетические реквизиты. Проверки службы в существующих unit-тестах заменены заглушками, реальных перезапусков нет.

```bash
python3 tests/test_snell_subscriptions.py
```

## Что ещё не сделано

CLI и чтение `/etc/snell/snell-server.conf` остаются v5. Новый внутренний API не означает поддержку v6 в установщике или TUI. До подключения v6 необходимо добавить явное хранилище модели endpoint, стабильный ID, подтверждённую серверную конфигурацию и транзакцию между службой и подписками. Нельзя просто дописать version=6 в существующий INI и ожидать включения v6.

Проверка реального Android-импорта, выдачи по HTTP и обновления работающего сервиса в этом этапе не проводилась. Публикации и изменения VPS не выполнялись.
