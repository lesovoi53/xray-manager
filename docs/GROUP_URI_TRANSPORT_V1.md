# URI-контейнер групп для неизменённых панелей: tuna-groups v1

Статус: реализован на серверной стороне и проверен локально; поддержка клиента делается
отдельно в задаче «tuna vpn». Не считать текущий rc12 поддерживающим этот контейнер.

## Формат

```text
tuna-groups://v1/BASE64URL_NOPAD_UTF8_JSON
```

- Payload — UTF-8 полного документа `tuna.subscription`, schemaVersion=1, как `/sub-json/TOKEN`.
- Base64URL: только A-Z, a-z, 0-9, _, -; без padding `=`, без zlib/gzip, BOM и переноса строк.
- JSON содержит subscriptionId, revision, complete=true,
  requiredCapabilities=["connection-groups-v1"], profiles и groups.
- Сервер не добавляет query или fragment. Панель может добавить `#имя`; клиент отбрасывает
  fragment перед декодированием. Не применять percent-decode к payload и внутренним URI.
- `v1` — версия транспортного контейнера, не замена schemaVersion документа.
- Пустой полный snapshot тоже отправляется, чтобы клиент удалил ранее импортированные группы.
- Payload — данные с реквизитами. Это НЕ шифрование; не выводить URI в логи или аналитику.

## HTTP сервера

Новый `GET /sub-groups/TOKEN` возвращает text/plain, Cache-Control:no-store:
обычный Base64 от ASCII строки контейнера плюс LF. Прежние `/sub/TOKEN` (обычные URI)
и `/sub-json/TOKEN` (прямой JSON) остаются без изменения.
`GET /api/users/ID/subscription-url` добавляет поле `group_transport_subscription_url`.
Пункт 7 TUI показывает оба адреса с пояснением назначения.

Обёртка работает поверх уже проверенного атомарного snapshot. Предел всего HTTP тела —
2 МиБ, включая оба Base64 слоя: это совместимо с пределом загрузчика внешних подписок LuckUI.
Неизвестный или отключённый token → 404; повреждённый snapshot или превышение размера → 500,
без частичного документа. Токен нового маршрута маскируется в журнале HTTP.

## Подключение к LuckUI без изменения обработчика

Сохранить обычный внешний источник `/sub/TOKEN`.
У существующего внешнего источника групп заменить ТОЛЬКО путь `/sub-json/TOKEN`
на `/sub-groups/TOKEN`; оставить тот же token, клиентскую привязку, enable, срок и порядок.
Не добавлять третий источник и не оставлять старый JSON-источник активным — он по-прежнему
будет портить смешанную выдачу. Публичный URL панели, порты и её бинарник не изменяются.
Это изменение настройки источника, а не патч обработчика LuckUI, и требует разрешения на запись.
Панель кэширует внешние источники пять минут; новый URL имеет отдельный ключ кэша.

## Требования для клиента (переданы в «tuna vpn»)

При импорте обычного raw/Base64 списка сначала отделить контейнеры от обычных URI.
Проверять схему, версию, алфавит, размер и строгий JSON. Не импортировать контейнер как VPN Profile.
После отделения fragment восстановить padding только для Base64 decoder; декодировать UTF-8 строго.
Переиспользовать TunaSubscriptionDocument и SubscriptionGroups, включая проверку ссылок на ID,
семейства, лимиты и поддержку requiredCapabilities. Стабильные subscriptionId/revision/groups[].id
сохраняются; приоритеты/порядок/ссылки не переписываются. Некорректный контейнер должен приводить
к явному отказу импорта, без частичного обновления и удаления прежних групп.
Обработка нескольких документов/одинаковых URI, конфликтов и владения профилями должна быть
согласована в клиентской реализации; сервер выдаёт ровно один контейнер на этот endpoint.

## Проверки

На Debian 12 и 13: по 8 тестов TUI + 15 тестов API/групп — PASS.
Проверены round-trip JSON, пустой snapshot, отзыв доступа, повреждение документа,
размер с учётом двойной Base64, новый HTTP endpoint, discovery-ссылка, Content-Length,
маскирование токена и неизменность старых форматов.

Go harness с функциями точного установленного коммита LucX
89a5f758a1d54808b5dff31d8bf310d544cac3ba:
- воспроизведено повреждение сырого JSON;
- прежние plain/Base64 URI проходят;
- фактический контейнер, выданный нашим Store.publish_uri на синтетическом fixture,
  проходит decodeSubscriptionBody → linkDisplayName → prefixedLinkName → applyRemarkToLink,
  включается в Base64 публичного списка и декодируется обратно в побайтно одинаковый JSON,
  как без name_prefix, так и с ним.

Эта локальная проверка не заменяет живой запрос к панели и проверку нового клиента на телефоне.
Развёртывание ещё не выполнялось на момент подготовки спецификации. Второй сервер на паузе.
