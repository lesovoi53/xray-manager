# Публичная выдача групп через внешние подписки LucX-UI: диагноз

Дата: 26 сентября 2026. Развёртывание не выполнялось. Панель изменять запрещено пользователем.

## Установлено на сервере (только чтение)

Пользователь подтвердил, что TUNA и LuckUI находятся на одном старом сервере 31.76.75.167.
Версия панели из Go build info: v3.8.5-lucx.265,
commit 89a5f758a1d54808b5dff31d8bf310d544cac3ba, vcs.modified=false.
Службы tuna-subscriptions и x-ui active. В client_external_links две записи kind=subscription:
локальный /sub/ и локальный /sub-json/. Секретные URL и данные клиентов не записывались в отчёт.

- TUNA /sub/: HTTP 200, text/plain, 3148 байт Base64, 6 URI, JSON групп отсутствует.
- TUNA /sub-json/: HTTP 200, application/json, 2866 байт, корректный полный JSON,
  schema=tuna.subscription, 1 группа, 7 профилей.
- Публичная подписка панели: HTTP 200, 13320 байт, Base64; до вложенного JSON — 18 строк URI.
  JSON повреждён, strict decoder сообщает offset 980. Префикс до первого # совпадает с исходным
  JSON, далее присутствуют percent-encoded JSON quotes. Простое обратное unescape не восстановило
  полное байтовое равенство; чинить ответ на клиенте эвристикой нельзя.

Значения относятся к конкретным запросам, не являются обещанием неизменного содержимого.
Подписки запрашивались без изменения конфигурации; обычный GET панели может обновлять её штатные
счётчики/время получения и кэш. Перезапусков и команд изменения настроек не выполнялось.

## Точная причина по исходникам установленного коммита

1. internal/sub/external_subscription.go, decodeSubscriptionBody: разбиение на строки;
   strings.Contains(ln, "://") достаточно, чтобы признать строку ссылкой.
   Наш компактный JSON содержит URI и поэтому целиком становится одним элементом списка.
2. internal/sub/external_config.go, expandEntry → linkDisplayName: первый # внутри первого
   URI документа принимается за fragment всей строки, остаток проходит PathUnescape.
3. applyRemarkToLink: обрезает строку по первому # и дописывает PathEscape(remark).
   В результате кавычки и структура оставшейся части JSON становятся percent-encoded.
4. internal/sub/service.go, getSubs добавляет результат к обычным ссылкам;
   controller.go, subs соединяет строки и выдаёт Base64.

Это не ошибка сохранения группы в TUNA и не доказательство несовместимости протокола VPN.
Это несоответствие JSON-документа формату входа обработчика внешних подписок панели.

## Проверка клиентского контракта

Прочитана текущая рабочая копия TunaTURN (в ней есть чужие незакоммиченные изменения; не трогалась).
ProfileManager.kt: ветка TunaSubscriptionDocument.parse включается только для корневого JSON
с schema=tuna.subscription до обработки Base64 строк. tryParseBase64TextSubscription передаёт
результат в tryParseTextSubscription. Внутри списка контейнеры tuna://, wireturn://, wt://
декодируются как Profile или List<Profile>, не как документ внешних групп.
SubscriptionGroups.kt сопоставляет группы по profiles[].id и routingProfileId.
Следовательно, простая упаковка JSON в уже существующий контейнер на сервере не доказывает
доставку групп: без отдельной поддержки групп на клиенте это другой контракт.

## Локальные проверки

- Временный Go harness использует функции точного коммита панели; воспроизведено принятие JSON
  за URI и порча после fragment. Обычные plain/Base64 URI по-прежнему декодируются.
  Местоположение: ../lucx-subscription-inspect/repro, 2 теста PASS.
  Для изоляции вместо upstream go-json используется стандартный encoding/json;
  полный бинарник панели не собирался и не менялся.
- test_connection_groups.py: добавлены проверки реальных HTTP /sub/ и /sub-json/,
  полного потребления JSON строгим декодером, сохранения percent-encoded URI без изменений,
  неизменности обычной выдачи после сохранения группы и после повреждения JSON в тестовой БД.
  Синтетическое склеивание URI + JSON воспроизводит недопустимый внешний envelope.
- Debian 12 и 13: по 8 тестов меню и 13 тестов групп PASS.
- Изменён только файл серверных тестов и добавлен этот отчёт. Рабочие сервисы, код панели,
  клиент, VPN-конфигурации, порт, токены и настройки второго сервера не изменены.

## Граница исправления и ожидаемое решение

Пользователь запретил изменение обработчика панели. Предложено уточнить один из путей:
1. Одна внешняя подписка через неизменённый LuckUI: новый контейнер групп в URI-строке,
   согласованный между НАШИМ сервером и НАШИМ клиентом. Не выдавать неподдержанный клиентом
   контейнер как готовое исправление. Старую Base64 выдачу сохранить совместимой/отдельной.
2. Только сервер: отдельный публичный JSON endpoint, доставляющий /sub-json/ без обработки
   списком URI. Публичный маршрут ещё не согласован; TUNA по принятому требованию остаётся
   loopback-only. Не открывать 22217 наружу и не занимать новые 443/8443 самовольно.

До выбора пути менять тело /sub-json/ под эвристику LuckUI нельзя: это повредит прямым клиентам
и не научит текущий line parser импортировать группы. Развёртывание требует явного разрешения.
Второй сервер 78.17.25.8 остаётся на паузе до приёмки старого.
