# Результат серверной доработки Snell/Mieru, 01.10.2026

> Исторический отчёт этапа 01.10.2026. Его статусы публикации и внедрения относятся к тому этапу. Исправления включены в выпуск [v2026.10.02.1](RELEASE_20261002.md); ниже сохранены исходные границы проверок.

Локальная реализация и перечисленные ниже лабораторные проверки завершены.
Новый выпуск не опубликован. Развёртывание этой версии целиком на VPS не выполнено.
На тестовом сервере ранее установлена только UDP-правка Snell; подробности ниже.

## Соответствие требованиям

| Требование | Реализация | Проверка / граница |
|---|---|---|
| Snell DNS через политику Xray | TCP REDIRECT; UDP mark → policy → TPROXY | Реальный Xray в namespace; DNS/HTTPS на тестовом VPS в предыдущем этапе |
| Не скрывать неверный gateway | Проверка конфигурации, слушателя, UDP transparent, routing policy | Неполная конфигурация и коллизии отклоняются |
| Безопасный повтор и смена режима | Собственные цепочки, проверка ownership, сохранение routing.mode после успеха | Повтор, direct/xray, сбой применения и откат PASS |
| Общий откат установки | Снимок policy rule/table, восстановление без глобального ip rule flush | Полный update и отказ службы при активном TPROXY; возврат к direct PASS |
| Согласованный Mieru | Одна модель из Mita RPC + штатного protobuf codec | Mode 32/48, RIGHT_7, LEFT_14, NO_ROTATION; оба shell-пути PASS |
| Без массового изменения подписок | Явный preview/repair одного URI с SHA-256, ID, revision, проверкой реквизитов/паттерна | Внешние ссылки, другие пользователи, токены, IDs групп сохранены; коллизии отклоняются |
| Адресный откат Mieru | change.json + проверка неизменности выбранной записи | Новые изменения чужого пользователя сохранены; повторный/устаревший откат отклоняется |
| Сохранить рабочий Mieru на тестовом VPS | Конфигурации и записи не менялись | Клиентская задача сообщила об успешных HTTPS/DNS/WebView на rc11 |

## Изменённые файлы

- `scripts/snell-routing.py`, `scripts/snell-routing.sh`: прозрачный UDP,
  preflight, повторное применение, откат, транзакционное сохранение режима.
- `scripts/installer-state.py`: снимок и восстановление собственного policy slot;
  запуск управляемого core перед зависимыми службами при rollback.
- `scripts/mieru-subscriptions.py`: общий экспорт, validation, preview/repair/restore.
- `bin/x-manager`: оба экспорта Mieru через helper; отказ не создаёт пустую ссылку;
  Snell TUI не сохраняет ложный режим. Выбор Mieru-пользователя сохраняет пробелы.
- `install.sh`: установка новых helpers, включая зависимости Snell до ExecStartPre.
- `tests/test_mieru_subscriptions.py`, `tests/test_snell_routing.py`,
  `tests/lab-mieru-export.py`, `tests/lab-snell-network.py`,
  `tests/lab-snell-installer.py`: новые регрессии и реальные daemon/kernel-проверки.
- [Инструкция установки, обновления, ремонта и отката](SNELL_UDP_MIERU_EXPORT.md).

## Фактические локальные проверки

- Debian 12 и Debian 13: по **68 тестов менеджера и 79 тестов TUNA**, PASS.
  На Python 3.13 наблюдались ResourceWarning о незакрытых SQLite connections;
  сообщения не подавлялись и не превращались в «чистый» журнал.
- Настоящий Mita daemon в Debian 13: RPC → экспорт → native codec для mode32
  и mode48, PASS; исходная лабораторная конфигурация восстановлена.
- Настоящий Xray в отдельных namespace: прежний UDP REDIRECT-дефект воспроизведён;
  новый путь UDP/TCP A/AAAA, повторные UDP в одном socket, повтор без дубликатов,
  direct/xray, отказ NAT после применения mangle, конфликт чужого rule — PASS.
- Debian 13 с systemd: чистая `--direct`, повторная `--update`, активные службы,
  API TUNA HTTP 200, WebDAV PROPFIND 207, multi-mode от wdavtunnel — PASS.
- Сохранение остановленной/disabled службы — PASS.
- Update существующей лабораторной установки: сохранены хеши конфигураций,
  пользователи, токены, ревизии, порты, ключи и содержимое старой подписки — PASS.
- Недоступная зависимость, ошибка загрузки, неверная конфигурация,
  фактический отказ запуска Mita — ненулевой выход, прежняя установка сохранена
  или восстановлена; проверки данных/активности выполнены после каждого случая.
- Напечатанная установщиком команда постоянного rollback — PASS.
- Отдельно с работающим Xray и Snell TPROXY: update, реальный отказ Mita и
  общий rollback сохранили policy; откат к снимку до TPROXY удалил его rule/table
  и вернул direct, PASS.
- Bash syntax и `git diff --check` — PASS, дополнительно к поведенческим тестам.

Полный systemd lifecycle этой итерации выполнен на Debian 13. На Debian 12
этой итерации выполнены наборы регрессий; это не отдельная новая VPS-приёмка.

## Что действительно внедрено на VPS

На **31.76.75.167**, в предыдущем этапе этой задачи, внедрены:

- `/usr/local/bin/snell-routing.sh`;
- `/usr/local/share/x-manager/scripts/snell-routing.py` и `xray-discovery.py`;
- соответствующие копии в `distribution/scripts`.

Это более ранняя версия UDP-правки. Последующие изменения TUI, общего rollback
и Mieru из текущего checkout на VPS ещё не устанавливались. Службы в момент
внедрения UDP-правки не перезапускались; сверены хеши проверенных конфигураций,
PID/время запуска Snell, Mita, x-ui, WebDAV, OpenFlux 1–3, TUNA.

На VPS тогда прошли 12/12 DNS-проверок от UID snell:
три resolver × UDP/TCP × A/AAAA. Повторное применение не добавило правил.
Трассировка одного тестового запроса подтвердила исходное внешнее назначение,
upstream через Xray и ответ Snell. Реальный Windows Snell-клиент получил
gstatic 204 и Cloudflare 200 по домену и по фиксированному IP с Host/SNI и TLS
verification. В Windows-копии использовался tfo=false и совместимый v4 outbound;
исходный профиль не менялся. Это не доказательство Android или полной поддержки v5.

Точный откат **этого раннего внедрения на 31**:

```bash
python3 /var/backups/x-manager-snell-udp-vh0ouzx8/rollback.py
```

Он возвращает прежние файлы, NAT/mangle и policy без рестарта и изменения БД.
NAT/mangle возвращаются целиком: перед применением проверить, не менял ли другой
процесс firewall после снимка. Этот rollback в данном завершающем этапе не запускался.

**89.19.223.185 не обновлялся и в этом этапе не обследовался.** Его конфликт
Mieru-Home пока остаётся в production. Нужны приёмка 31 и отдельное разрешение
