# X-Manager v2026.10.07.1

Полный выпуск для Debian 12/13 amd64. Установщик и меню получают компоненты из
одного закреплённого выпуска `lesovoi53/xray-manager` с проверкой SHA-256.

## Изменения

- Единый раздел Snell v5/v6. Одна активная локальная версия, общий PSK,
  сохранение настроек неактивной версии. Snell v6 поддерживает режимы
  `default`, `unshaped`, `unsafe-raw` и обычный UDP relay через TCP.
  `unsafe-raw` не обеспечивает шифрование/проверку PSK; QUIC Proxy не включён.
  Редактирование подписки отделено от настройки серверных служб.
- Явные состояния служб: ручной stop, постоянное off и отдельный автозапуск.
  Обновление и собственные watchdog учитывают эти состояния. Пустые слоты
  Snell скрыты; OpenFlux объединён в один пункт с подменю каналов.
- Для OpenFlux общий сохраняемый бюджет восстановления: по умолчанию
  20 попыток на все каналы, пауза 30 секунд. Для других служб новая базовая
  политика — 5 повторов, пауза 30 секунд. Для проверки Xray внутри X-UI —
  2 последовательные ошибки, до 5 восстановлений с паузой 60 секунд.
  Уже существующие пользовательские политики не заменяются этими значениями.
- Автоматический бюджет памяти OpenFlux при установке и перед запуском.
  Учтены память системы/cgroup, резервы ОС и других служб, все настроенные
  каналы. Ручной бюджет сохраняется. Отчёт показывает МиБ, текущие значения
  и ожидающие применения изменения. GOMEMLIMIT — мягкая цель Go, не предел RSS.
- Исправлены сохранение указанных комнат Cups после перезапуска, накопление
  записей потоков Cups и направление heartbeat Engine.IO v4 Яндекс Досок.
  Протоколы, ключи и пользовательские ссылки этими патчами не заменяются.
- Диагностика сети, поиск конфликтов watchdog и отдельный добровольный профиль
  сетевых настроек с резервной копией. Пустой список конфликтов объясняется
  словами; машинный JSON сохранён для программных вызовов.

## Обновление через меню

1. Создайте резервную копию и сохраните её путь. Полный установщик также создаёт
   собственную резервную копию перед заменой управляемых файлов.
2. Если работает сторонний `vpn-watchdog.service` или `vpn-watchdog.timer`,
   явно остановите его перед обновлением. Установщик откажет до изменений,
   пока такой наблюдатель активен. Это предотвращает перезапуск служб
   сторонней автоматикой во время замены файлов и отката.
3. Откройте `x-manager` → **Обслуживание → Обновить полный выпуск**.
   Обновлятор определяет GitHub Latest один раз, скачивает `x-manager.tar.gz`
   и `SHA256SUMS` одного тега, проверяет архив и запускает `install.sh --update`.
4. После успешного завершения откройте состояние служб, диагностику памяти,
   подписки и проверьте реальные подключения своим клиентом.

Этот выпуск не меняет Xray-панель на другую и не устанавливает клиент TUNA.
Обновление может перезапустить разрешённые управляемые службы. Ручные stop/off,
существующие UUID, ключи, порты и данные подписок должны сохраняться.

## Откат

В меню используйте **Обслуживание → Восстановить резервную копию**, указав
нужный каталог `/var/backups/x-manager-*`. При недоступном меню используйте
сохранённый `installer-state.py` из этой копии:

```bash
python3 /var/backups/x-manager-НУЖНАЯ-КОПИЯ/installer-state.py restore /var/backups/x-manager-НУЖНАЯ-КОПИЯ
```

Откат выполняется от root, без параллельной установки и при остановленном
внешнем watchdog. Он восстанавливает управляемые файлы, базы и состояния служб;
изменения данных после даты снимка будут потеряны. Перед обновлением сохраняйте
копию помощника вне заменяемого каталога программы. Пакеты ОС не откатываются.

## Проверки и границы

- Текущий код: 295 тестов установщика/служб/меню и 98 тестов подписок прошли
  в изолированной Debian 12. Это не результат обновления рабочего сервера.
- Автобюджет: 5 сценариев настоящего systemd в изолированной Debian 13,
  включая непривилегированный runner, повтор, ручной бюджет и отказ запуска
  при недостаточном бюджете. Сетевой бинарник заменён изолированным fixture.
- На разрешённом тестовом VPS проверены сохранение конфигураций и состояния
  при обновлениях кандидата; последние правки меню/RAM установлены без
  перезапуска. Работающие каналы сохраняют прежний GOMEMLIMIT до следующего старта.
- Подробные протокольные и транзакционные проверки разных этапов находятся в
  `SNELL6_*`, `SNELL_EXCLUSIVE_ACCEPTANCE_20261007.md`,
  `OPENFLUX_MEMORY_20261007.md` и `IMPLEMENTATION_ACCEPTANCE_20261007.md`.
  Исторические хэши кандидатов в этих отчётах не являются хэшем финального архива.
- Обновление производственного сервера 89 через GitHub-меню остаётся ручной
  приёмкой владельца. Публикация не означает, что оно уже выполнено.
- Длительная нагрузка, все сочетания клиентских режимов и все сторонние
  watchdog не подтверждены этим выпуском. Сохранены конкретные границы прежних
  тестов; наличие настройки не выдаётся за универсальную совместимость.
