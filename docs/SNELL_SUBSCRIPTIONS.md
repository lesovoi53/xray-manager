# Snell и подписки TUNA: v2026.10.01.1

В старом генераторе профиля TUNA отсутствовали `obfs-mode` и `obfs-host`, а имя
всегда было `Snell-v5`. Экспорт из меню Snell использовал другой генератор.
Исправление объединяет генерацию и добавляет явную привязку локальных ссылок.
Бинарник Snell, версия протокола и настройки шифрования не изменены.

## Использование

Новый пользователь, созданный из служб сервера, получает актуальные параметры
Snell и автоматическую привязку. Экспорт Snell использует тот же генератор.
При изменении обфускации, имени, ключа или порта в меню Snell связанные ссылки
обновляются после успешного применения настроек. Пользовательские `reuse`,
`tfo` и дополнительные параметры существующих ссылок сохраняются.

Для старой подписки: **TUNA → пользователь → Snell → [4] Синхронизировать
локальный Snell и включить автообновление его ссылки**. Операция разрешена только
при единственном совпадении адреса, порта, PSK и версии. Совпадения только IP
недостаточно. При неоднозначности данные не меняются; требуется выбрать и
исправить запись вручную. Автоматического захвата всех старых ссылок нет.

Эквивалент для администратора (значения заменить своими):

```bash
python3 /usr/local/share/x-manager/scripts/snell-subscriptions.py adopt \
  --server-ip SERVER_IP --user USER_UUID
```

UUID пользователей, токены, остальные протоколы, внешние ссылки и настройки групп
сохраняются. Точные копии связанного URI в группах обновляются с сохранением ID
профиля и его пользовательского имени. При конфликте с другим профилем операция
отменяется, профили автоматически не сливаются. Ревизия повышается один раз на
изменённого пользователя. Повторный запуск без изменений ревизию не повышает.

Стандартная подпись `Snell-v5` после привязки следует имени службы; явно заданное
пользователем имя ссылки сохраняется. Значение `0`, уже записанное как имя службы,
не исправляется молча. В новом диалоге переименования `0` означает отмену, пробелы
внутри имени сохраняются.

Пункт полной пересборки профиля по-прежнему заменяет ссылки всех основных
протоколов после подтверждения. Для ремонта только Snell используйте пункт [4].

## Транзакция и восстановление

Перед изменениями создаётся закрытый каталог `/var/backups/x-manager-snell-*`
с конфигурацией, именем (если было), SQLite backup API-снимком базы и, при смене
порта, правилами iptables. Конфигурация заменяется атомарно с сохранением владельца
и прав. Во время изменения SQLite удерживает транзакцию; отказ службы или записи
откатывает БД и возвращает прежние настройки. Если сам откат не удался, команда
завершается ошибкой с путём к копии. Успех при неудачном рестарте не печатается.

При изменении порта проверяются TCP и UDP, запрещены новые 443/8443. Только
распознанные правила Snell переносятся на новый порт на прежних позициях;
политика DROP/ACCEPT и правила других служб сохраняются. Настройки работающего
Snell меняются с проверкой службы; для остановленного Snell сначала требуется
явно запустить службу. Переименование и синхронизация подписок не перезапускают её.

После аварийного завершения процесса/питания сравните конфигурацию и базу с копией.
Автоматического восстановления после SIGKILL нет. Перед ручным восстановлением
сохраните текущее состояние; полная замена базы уничтожит более поздние изменения
других пользователей. Для восстановления только Snell перенесите нужные
`snell_uri`, ревизии и записи `x_manager_snell_links` из SQLite-копии в транзакции.
Для полного отката установки используйте её отдельный snapshot и штатную команду
`install.sh --rollback /var/backups/x-manager-...`.

## Разработка

`scripts/snell-subscriptions.py` отвечает за чтение конфигурации, URI,
явные привязки и транзакцию. Метаданные находятся в таблице
`x_manager_snell_links(user_id, uri, follow_name)` в существующей базе TUNA.
Исчезновение/ручное изменение связанной строки отключает её привязку при следующей
синхронизации. Сравнение идёт с точным сохранённым URI, а не только с адресом.
Ручной повторный импорт профиля с новым URI сам по себе не связывает его со старым.

`bin/x-manager` вызывает helper для экспорта, создания и изменений. `install.sh`
устанавливает helper и синхронизирует уже привязанные записи, не усыновляя ручные
записи. Резервирование установщика включает helper, базу и сохранённый дистрибутив.

Тесты: `python3 -m unittest discover -s tests -p test_snell_subscriptions.py -v`.
Проверяются реальные shell-функции генерации, HTTP/off, кодирование, сохранность
ключей/токенов/внешних ссылок, группы и коллизии, идемпотентность, отказ запуска,
откат и сохранение порядка firewall. Работоспособность ссылки в клиенте требует
отдельной проверки подключения; HTTP 200 подписки её не заменяет.
