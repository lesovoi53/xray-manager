## Назначение и архитектура

X-Manager связывает независимые транспортные программы, локальные шлюзы Xray и персональные подписки TUNA. Основная программа — Bash, сервер подписок и вспомогательные утилиты используют стандартную библиотеку Python. Это не собственное VPN-ядро, не панель управления произвольными Xray inbounds и не замена клиентскому приложению.

```text
Клиент → выбранный транспорт → служба на VPS → Direct → сеть
                                        └→ локальный шлюз Xray → правила Xray → сеть

x-manager → конфигурации и systemd
          → локальное API TUNA → SQLite → Base64 / JSON
                                         ↓
                              ваш локальный сервис-получатель
```

### Что устанавливается

| Компонент | Поведение выпуска |
|---|---|
| Snell 5.0.1 | Установка бинарника, конфигурации, службы и маршрутизации |
| Mieru / mita 3.38.0 | Установка сервера и интеграции с Xray/Direct |
| OpenFlux d13aa5b7 + патч | Установка бинарника, восьми конфигураций экземпляров и шаблона systemd; для работы нужны ссылки каналов |
| WebDAV Tunnel b1af4c05 | Установка бинарника, runner, конфигурации и службы |
| TUNA | Локальный HTTP-сервис, SQLite, редактор пользовательских групп |
| CottenDNS / MasterDnsVPN | Дополнительная установка через меню DNS, не обязательный этап основной установки |
| Xray / WDTT / CSQTT | Работа с существующей установкой; их бинарники основной установщик не загружает и не заменяет |

Точные версии и SHA-256: [components.json](../components.json). Бинарники и соответствующие архивы исходников публикуются в собственном [GitHub Release](https://github.com/lesovoi53/xray-manager/releases/tag/v2026.09.26.3). Пакеты ОС устанавливаются из APT Debian. Это не полностью автономная установка без сети: используются GitHub, APT, определение внешнего IP и, при работе соответствующих транспортов, внешние облачные API.

### Связь с Xray

| Шлюз | Требования | Использование |
|---|---|---|
| SOCKS5 | 127.0.0.1, без авторизации | Egress Mieru и DNS-туннелей |
| REDIRECT | Совместимый dokodemo-door с followRedirect | Правила перенаправления Snell, OpenFlux, WebDAV |
| TPROXY | Совместимый dokodemo-door, tcp/udp, режим tproxy | Интеграция WDTT |

Standalone-конфигурация обнаруживается в стандартных каталогах, аргументах запущенного Xray или через `XM_XRAY_CONFIG`. Для обнаруживаемых standalone-шлюзов требуется listen `127.0.0.1`. Поддерживаются JSON/JSONC и каталоги конфигураций. Сам конфиг standalone Xray не перезаписывается. Если подходящих шлюзов несколько или сохранённое значение противоречит конфигурации, требуется устранить неоднозначность.

При наличии `/etc/x-ui/x-ui.db` работает отдельный адаптер базы панели, который может создавать или синхронизировать шлюзы. Это отличается от режима standalone. Полный произвольный формат любой панели не поддерживается автоматически.

Предпочтительные порты — 10808, 12345, 12346; свободный порт подбирается при необходимости. Сохранённые значения имеют приоритет. Новые управляемые порты 443 и 8443 запрещены; ранее сохранённый запрещённый порт вызывает понятный отказ, а не тихую замену. Подбор порта не создаёт недостающий шлюз в standalone Xray: его нужно подготовить в самом ядре.

## Установка

### Требования

- Debian **12 или 13**, архитектура **amd64 / x86_64**.
- Права root и работающий systemd.
- Доступ к APT Debian и собственным GitHub Releases проекта.
- `curl` и `tar` для первоначальной загрузки. Основной установщик устанавливает необходимые системные утилиты, включая Python 3, jq, iptables, OpenSSL и qrencode.
- Для Xray-режима — совместимые локальные шлюзы. На чистом VPS без Xray используйте явный Direct.

ARM64, Ubuntu и системы без systemd не являются поддерживаемой платформой этого выпуска. Минимальные RAM/CPU и обещания пропускной способности не заданы: соответствующего нагрузочного исследования не было.

### Получение полного комплекта

Команды ниже только скачивают, проверяют и распаковывают выпуск в новый каталог. При любой ошибке блок прекращается; имя готового каталога выводится в конце.

```bash
(
  set -euo pipefail
  tag=v2026.09.26.3
  base="https://github.com/lesovoi53/xray-manager/releases/download/$tag"
  stage=$(mktemp -d ./x-manager-install.XXXXXXXX)
  cd "$stage"
  curl -fL --proto '=https' --proto-redir '=https' "$base/x-manager.tar.gz" -o x-manager.tar.gz
  curl -fL --proto '=https' --proto-redir '=https' "$base/SHA256SUMS" -o SHA256SUMS
  grep '  x-manager.tar.gz$' SHA256SUMS | sha256sum -c -
  tar -xzf x-manager.tar.gz
  printf 'Каталог установщика: %s\n' "$PWD"
)
```

Перейдите в выведенный каталог. Выберите **один** режим:

| Команда | Назначение |
|---|---|
| `sudo bash install.sh --quick` | Автоматическая установка с обнаружением Xray; без аргументов используется этот же режим |
| `sudo bash install.sh --interactive` | Выбор быстрого или ручного режима; в ручном доступны выбор Snell/Mieru/OpenFlux, реквизиты, порты и маршрут |
| `sudo bash install.sh --direct` | Явный прямой выход для установки без Xray; существующие отдельные настройки не следует считать автоматически переведёнными в Direct |
| `sudo bash install.sh --update` | Применение уже скачанного полного выпуска с сохранением существующей конфигурации |

Алиасы интерактивного режима: `--manual`, `-m`, `-i`. Программа выбирает режим по первому аргументу; не объединяйте несколько режимов в одной команде.

Пример для нестандартного standalone-конфига:

```bash
sudo env XM_XRAY_CONFIG=/etc/custom-xray/config.json bash install.sh --quick
```

После установки выполните `sudo x-manager`. Настройте реальные ссылки OpenFlux и внешние учётные записи WebDAV, если используете эти режимы: установка бинарника не создаёт документы и аккаунты в облаках.

## Меню и быстрые команды

Главная содержит семь разделов: пользователи/подписки, службы, Xray, сеть/безопасность, диагностика, обновление/восстановление и справка. `0` возвращает назад или закрывает меню. Выход не останавливает службы и не запускает обновление.

В основных меню действия сгруппированы по подключению, настройкам, диагностике и обслуживанию. Вложенные специализированные редакторы могут дополнительно использовать буквенные команды и свободный ввод адресов, имён и реквизитов; не все страницы состоят только из числовых переключателей.

| Команда | Раздел |
|---|---|
| `x-manager` | Главная |
| `x-sub`, `x-tuna` | Пользователи и подписки |
| `x-snell` | Snell |
| `x-mieru` | Mieru |
| `x-openflux`, `x-flux` | OpenFlux |
| `x-webdav`, `x-wdav` | WebDAV Tunnel |
| `x-wdtt`, `x-qwdtt` | WDTT |
| `x-csqtt` | CSQTT |
| `x-dns` | DNS-туннели |
| `x-ssl`, `x-cert` | Сертификаты |
| `x-fw`, `x-firewall` | Фаервол |
| `x-opt`, `x-sys` | DNS системы, BBR, swap, Fail2ban |
| `tuna-groups USER_ID` | Прямой запуск редактора групп конкретного пользователя |

Точный перечень действий верхних меню хранится в [menu-actions.tsv](../scripts/menu-actions.tsv), навигация — в [menu-v2.sh](../scripts/menu-v2.sh). Номер пункта в подразделе не равен историческому номеру обработчика; ориентируйтесь на название.

## Службы и туннели

### Snell

Доступны просмотр статуса и сокетов, Xray/Direct, HTTP-обфускация, имя подключения, смена PSK, смена порта, ссылка `snell://`, QR-код и строка параметров для Surge, управление доступом через фаервол, живые логи и перезапуск.

Snell 5.0.1 — оригинальный бинарник. Свойства протокола принадлежат Snell; X-Manager формирует конфигурацию и маршрутизацию. QR-код — другой способ передать ту же ссылку, не отдельный протокол совместимости. Правила перенаправления TCP/UDP в коде не заменяют проверку реального UDP-трафика конкретного клиента.

### Mieru / mita

Доступны пользователи и пароли, имя подключения, отдельные порты и диапазоны, выбор транспортных привязок, Xray/Direct, Low-Entropy пресеты и конструктор параметров маски, экспорт ссылки/QR, фаервол, статус, сокеты, логи и перезапуск. Пункт обновления запускает обновление всего выпуска.

Low-Entropy и маскирование реализует upstream Mieru. Конкретный эффект в сети оператора зависит от условий. Ручное переключение использует сохранённый SOCKS-порт; перед изменением создаётся закрытая резервная копия конфигурации.

### OpenFlux

Сервер управляет восемью экземплярами `openflux@1`…`openflux@8`. Каждый имеет собственный env-файл; незаданный URL не считается готовым каналом.

В меню доступны:

- настройка выбранного канала или мастер всех восьми;
- переключение классического и Multi-Stream режима;
- выбор транспорта и кодека `legacy` / `batched`, ключ шифрования и отладка;
- маршрутизация Xray/Direct;
- экспресс-проверка ссылок и бенчмарк облачного API;
- последние/живые логи, запуск настроенных каналов, остановка и полное обновление.

Каталог подписок OpenFlux v2 допускает транспорты **mailru, boards, cupsonline**. Список возможностей ядра/старых каналов может быть шире; упоминание транспорта в upstream или старом меню не означает, что он допустим в клиентском bundle v2.

У пользователя выбираются 1–8 групп каталога, их порядок, общий режим `classic`/`multistream`, имя, connection ID и стратегия `roundRobin`/`leastPing`. Есть предпросмотр, импорт и экспорт. В обычную подписку добавляется одна строка `openflux-bundle://v2/...`.

Не путайте серверный экземпляр, группу каталога, bundle пользователя и внешнюю группу URL-test. Это разные уровни. Бенчмарк API облака не измеряет полную скорость VPN от телефона до конечного сайта.

### WebDAV Tunnel

Доступны режимы selfhosted, Mail.ru, Яндекс.Диск, произвольный WebDAV и multi-backend. Для провайдеров хранятся отдельные реквизиты; в пул можно включать локальное хранилище и внешние backends.

Меню позволяет менять URL/порт в применимых режимах, учётные записи, состав пула, флаг шифрования, Xray/Direct; выдавать ссылку/QR; выполнять авторизованный PROPFIND; смотреть логи; запускать, останавливать, перезапускать службу и обновлять полный выпуск.

Пул, TCP-туннель и криптографические механизмы реализует upstream WebDAV Tunnel. X-Manager добавляет управление, запуск, права каталогов, интеграцию маршрутизации и подписок. Флаг шифрования туннеля не делает HTTP endpoint автоматически HTTPS.

Каталог TUNA хранит отдельные подключения и их backends. Для пользователя доступны до восьми выбранных подключений, порядок, включение/исключение, настройка карточек, импорт из локального сервера или URI, ручное создание, предпросмотр и перенос ссылки подключения. Наличие backend в каталоге само по себе не запускает отдельную службу.

### WDTT / qwdtt

Для существующей установки: статус/сокеты, Xray через TPROXY или Direct, устройства и счётчики трафика, ссылка/QR, имя подключения, доступ через фаервол, логи и перезапуск. Установка и обновление самого qWDTT остаются за его собственным проектом.

### CSQTT

Для существующей установки: статус, сокеты, реквизиты, имя и ссылка/QR, смена логина/пароля, доступ к VPN-туннелю, открытие/закрытие веб-интерфейса снаружи, команда SSH-туннеля, логи и перезапуск. Отключение внешнего доступа к веб-интерфейсу не равно отключению VPN-службы.

### DNS-туннели

Доступны установка/удаление CottenDNS и MasterDnsVPN, переключение активного движка, настройка домена, ключа, имени, маршрута и WAN-доступа, логи и перезапуск. Экспортируются три профиля `stormdns://`: жёсткая цензура, стандартный, мобильный/скоростной. Это разные параметры профиля; сравнительная эффективность зависит от резолвера и сети.

Работа DNS-туннеля требует подходящей DNS-инфраструктуры. Меню не является регистратором доменов и не гарантирует автоматическую делегацию зоны у внешнего провайдера. Ручное переключение проверяет оба TOML-конфига до записи, подставляет числовой SOCKS-порт и восстанавливает файлы при отказе активной службы. Остановленная служба остаётся остановленной.

## Пользователи и подписки

Пользователя можно создать из обнаруженных служб сервера или из собственных URI. Редактор поддерживает имя, несколько узлов по протоколу, дополнительные ссылки, OpenFlux/WebDAV, пересборку профиля из активных служб и группы автовыбора. Ссылки на VLESS/Trojan/Shadowsocks/TUIC и другие поддерживаемые клиентом протоколы можно хранить; это не устанавливает соответствующий серверный inbound.

Операции обслуживания: включить/отключить пользователя, удалить, заменить токен, перезапустить сервис, посмотреть логи, обновить выпуск. Ротация токена намеренно отзывает старую ссылку; обычное обновление её не меняет.

Три разных состояния:

| Состояние | Значение |
|---|---|
| Служба systemd active | Процесс службы запущен |
| OpenFlux/WebDAV включён у пользователя | Соответствующие данные разрешено выдавать в его подписке |
| Проверка/измерение в клиенте | Клиент действительно проверил доступность/скорость подключения |

Список узлов, статус службы и флаг публикации не являются взаимозаменяемыми показателями.

### Получение вашим другим сервисом

Согласованная схема — **localhost-only**: `127.0.0.1:22217`. Сервис-получатель запрашивает подписку локально. Публикация API управления во внешнюю сеть не нужна.

- `GET /sub/TOKEN` — прежняя Base64-подписка со списком URI; поддерживает ETag/304.
- `GET /sub-json/TOKEN` — JSON `tuna.subscription`, версия схемы 1, capability `connection-groups-v1`.
- `GET /health` — проверка HTTP-сервиса.

JSON групп формируется из коллекции профилей/групп: наличие старых ссылок само по себе не создаёт все профили в этой коллекции. Для переноса доступно явное действие импорта в редакторе. Оба формата используют секретный токен пользователя.

База хранит URI, реквизиты, открытые токены и хеши токенов. Поиск подписки выполняется по SHA-256; открытый токен нужен для повторной выдачи ссылки администратору. Локальное API и резервные копии требуют доверенного окружения. Некоторые вложенные карточки показывают реквизиты, поэтому запись экрана меню может содержать секреты.

Подробности: [справочник сервера подписок](../tuna-sub-server/README.md).

## Группы URL-test и Speedtest

Путь: **Пользователи и подписки → Пользователи → Редактировать / группы URL-test и Speedtest → пользователь → Группы автовыбора**. Можно запускать `tuna-groups USER_ID`.

Редактор позволяет создавать, редактировать, переименовывать, включать/исключать и удалять группы; менять состав, порядок участников и профиль маршрутизации; добавлять/редактировать/удалять профили, импортировать их из обычной подписки этого пользователя, показать JSON-ссылку и реквизиты.

| Поле | Допустимые значения/назначение |
|---|---|
| Семейство | VPN, CSQTT_QWDTT, WEBDAV, OPENFLUX |
| Категория | VPN для семейства VPN; BYPASS для остальных трёх |
| Тип | URL_TEST или SPEEDTEST |
| Стратегия | BEST или PRIORITY, исполняется клиентом |
| Состав | 2–1000 уникальных профилей одного семейства |
| Профиль маршрутизации | Ссылка на одного из участников группы |
| Параметры | URL/HTTP-метод/ожидаемый статус, таймаут, интервал, удержание, подтверждения, порог улучшения, актуальность |
| Дополнительные параметры | Число запросов URL-test; длительность/лимит байт Speedtest; разрешение мобильной сети, автоматические проверки и проверка при подключении |

Создание URL-test предлагает известные HTTPS endpoint. Для Speedtest нужно указать непустой HTTPS URL файла; GET обязателен. Полный перечень полей и диапазонов проверяется [валидатором](../tuna-sub-server/tuna_connection_groups.py).

Профиль содержит стабильные ID, имя и URI; один профиль можно использовать в нескольких группах. Смешивание семейств и дубли запрещены. Для OPENFLUX нужен bundle v2; DNS-профили в эти внешние группы не входят.

Сохранение использует expectedRevision. Неверный документ отвергается целиком, параллельная правка возвращает конфликт. При ошибке сохранения завершённый черновик можно повторить или отбросить; он находится в памяти и не переживает закрытие процесса/SSH.

Измерения и переключение выполняет клиент после подключения. Сервер не тестирует VPN от имени телефона. Внешняя группа OPENFLUX не заменяет внутренний балансировщик bundle. [Контракт rc11 и проверенные сценарии](CONNECTION_GROUPS_RC11.md).

## Сеть и система

| Раздел | Действия | Граница |
|---|---|---|
| Фаервол | Разрешить/запретить доступ к Mieru, Snell, WDTT, CSQTT VPN/веб и DNS; массовая блокировка/открытие | Правила iptables управляют доступом, а не обязательно состоянием процесса; массовый пункт не является полной изоляцией всех возможных служб VPS |
| SSL | Поиск локальных сертификатов, пути/домен/срок действия, проверка OpenSSL | Собственного выпуска и продления ACME в этом меню нет |
| SSL при наличии панели | Синхронизация сертификата и памятка панели | Эти пункты скрыты без поддерживаемой базы 3X-UI |
| DNS системы | Выбор провайдера с замерами ping, применение/сброс resolver-настроек | Ping сервера DNS не измеряет качество DNS-туннеля |
| BBR | Включение и настройка сетевых буферов с учётом RAM | Не доказательство увеличения скорости в любой сети |
| Swap | Создание/изменение файла 2 или 4 ГБ, удаление, swappiness | Меняет дисковую/системную конфигурацию |
| Fail2ban | Установка/настройка SSH jail, обнаружение порта, список банов, ручной бан/разбан и время бана | Реакция на подходящие события журналов, не универсальная защита сервера |
| Диагностика системы | Характеристики сервера и сети, сводный статус служб | Отдельно от клиентской проверки подключения |

Настройки BBR, swap, системного DNS, Fail2ban и ручные операции меню не следует считать автоматически включёнными в транзакционный откат основного установщика.

## Обновление и восстановление

### Обновление

В меню: **Обновление и восстановление → Обновить полный выпуск**. Установленный updater также можно вызвать напрямую:

```bash
sudo bash /usr/local/share/x-manager/scripts/update-release.sh
```

Для конкретного выпуска:

```bash
sudo bash /usr/local/share/x-manager/scripts/update-release.sh v2026.09.26.3
```

Updater выбирает один тег, скачивает полный архив и SHA256SUMS, проверяет хеш и допустимость содержимого архива, запускает установку. Установщик проверяет платформу и зависимости, скачивает выбранные закреплённые бинарники, затем резервирует управляемое состояние и заменяет файлы. SHA-256 проверяет целостность относительно опубликованного манифеста; отдельной подписи независимым ключом здесь нет.

Сохраняются существующие конфигурации и реквизиты, пользовательские подписки, ранее остановленные службы и их автозапуск. Активные управляемые службы могут перезапускаться — текущие соединения могут прерваться. При успехе меню запускается из нового файла. Новая upstream-версия компонента не попадает на VPS сама: сначала нужен новый согласованный выпуск X-Manager.

### Откат

Перед заменой создаётся закрытый каталог `/var/backups/x-manager-XXXXXXXX`. Установщик печатает его путь. После частичного сбоя выполняется восстановление; если оно тоже не удалось, выводится отдельная ошибка.

Ручной путь: **Обновление и восстановление → Восстановить резервную копию**, выбрать снимок и подтвердить. Команда:

```bash
sudo bash /usr/local/share/x-manager/distribution/install.sh --rollback /var/backups/x-manager-XXXXXXXX
```

Замените `XXXXXXXX` реальным именем своей копии. При восстановлении управляемые службы останавливаются; состояние данных и правил iptables возвращается к снимку. При наличии панели операция восстановления затрагивает и её сохранённую базу/службу. Более новые изменения после снимка будут потеряны в восстанавливаемой области.

В снимок входят выбранные конфиги/бинарники/юниты, дистрибутив, SQLite подписок (включая нестандартный путь из config.toml), поддерживаемая база панели, состояние служб и IPv4 iptables. SQLite сохраняется через backup API с учётом WAL.

Это **не полный образ VPS**: APT-пакеты и системные пользователи не удаляются при откате; snapshot не охватывает все сторонние службы, отдельные DNS-движки, IPv6/nftables как самостоятельный набор или содержимое WebDAV-хранилища `/var/lib/webdav-tunnel/data`. Для такого восстановления нужна отдельная резервная копия. Точная область задана в [installer-state.py](../scripts/installer-state.py).

## Файлы и диагностика

| Путь | Назначение |
|---|---|
| `/usr/local/bin/x-manager` | Меню |
| `/usr/local/share/x-manager/components.json` | Установленный манифест компонентов |
| `/usr/local/share/x-manager/scripts/` | Утилиты обновления, обнаружения, меню и конфигураций |
| `/usr/local/share/x-manager/distribution/` | Постоянный полный комплект установщика |
| `/etc/x-manager/gateways.env` | Сохранённые порты шлюзов |
| `/etc/snell/snell-server.conf` | Snell |
| `/etc/mita/config.json` | Mieru |
| `/etc/openflux/instances/1.env`…`8.env` | Каналы OpenFlux |
| `/etc/webdav-tunnel/config.env` | Режимы и реквизиты WebDAV |
| `/etc/webdav-tunnel/webdav-tunnel.yaml` | Генерируемый конфиг multi-backend |
| `/etc/tuna-subscriptions/config.toml` | Настройки локального HTTP-сервиса |
| `/var/lib/tuna-subscriptions/subscriptions.db` | SQLite подписок по умолчанию |
| `/var/backups/x-manager-*` | Снимки основного установщика |

Для проверки без вывода подписок и реквизитов:

```bash
systemctl is-active snell mita webdav-tunnel tuna-subscriptions
systemctl is-active openflux@1 openflux@2
ss -lnt 'sport = :22217'
curl -f http://127.0.0.1:22217/health
```

Проверяйте только настроенные экземпляры: незадействованные каналы могут быть остановлены намеренно. Журнал нужной службы открывается из меню или через `journalctl -u ИМЯ_СЛУЖБЫ`. Не пересылайте необработанные конфиги, подписки или полный журнал без проверки на секреты.

| Симптом | Что проверять |
|---|---|
| Служба работает, но подключения нет в подписке | Флаг публикации у пользователя, выбор и включение записи каталога |
| Установка не находит Xray | Конфиг, loopback, совместимые inbounds, явный XM_XRAY_CONFIG; для чистого Direct — соответствующий режим |
| Старый порт запрещён/конфликтует | План портов завершился до переназначения; требуется осмысленная корректировка сохранённых настроек |
| OpenFlux не стартует | Настроен ли URL, соответствует ли транспорт, доступны ли облако и его API |
| WebDAV сообщает об авторизации | Режим и соответствующая пара реквизитов; PROPFIND проверяет доступ к WebDAV, не весь VPN-туннель |
| Группа не сохраняется | Минимум два участника, одно семейство, верный URL/диапазоны и актуальная ревизия |
| Подписка 127.0.0.1 не открывается на телефоне | Это ожидаемо: адрес предназначен для локального сервиса-получателя |

## Проверки и ограничения

При приёмке 25 сентября прошли 85 автоматических тестов, чистая/повторная установка в Debian 12/13, обновление с сохранением данных, отказы зависимости/загрузки/конфига/службы, откат, тест standalone Xray 26.9.9 и локальный SOCKS HTTP обмен. На рабочем VPS проверены службы, неизменность данных, выдача подписок и WebDAV PROPFIND. [Отчёт с фактическими результатами](VPS_DEPLOYMENT_20260925.md).

При подготовке этой документации новые VPS/клиентские тесты не запускались. Сообщение владельца о рабочем состоянии не расширяет автоматически набор выполненных нами проверок.

Известные границы выпуска:

- В v2026.09.26.1 исправлены ручные переключатели Mieru/DNS: сохранённый порт, проверка конфигураций, резервирование и отказ без ложного успеха. Проверки и границы обновления описаны в [отчёте исправления](MANUAL_ROUTING_FIX_20260926.md).
- Полный аудит и проверка всех старых обработчиков меню не проведены; транзакционность установщика не означает транзакционность каждого ручного действия.
- Не выполнены нами импорт в Android rc11, реальные измерения URL-test/Speedtest, сквозной UDP/TPROXY и трафик через каждый внешний транспорт. Проверка одной версии Xray не доказывает совместимость со всеми версиями/конфигами.
- Фиксация бинарников не фиксирует внешние API Яндекса/Mail.ru/Cups и не гарантирует их будущую доступность.
- Наличие функции в коде, успешный запуск процесса и работа полного клиентского соединения — разные уровни подтверждения.

Сравнение оригиналов и вклада сборки: [UPSTREAM_COMPARISON.md](UPSTREAM_COMPARISON.md).


### Настройки группы автовыбора (v2026.09.26.3)

В редакторе пользователя откройте «Группы автовыбора» → «Создать группу».
Выберите URL_TEST или SPEEDTEST, затем семейство VPN / CSQTT_QWDTT / WEBDAV / OPENFLUX.
Откроется единая форма: имя, режим, адрес проверки, допуск, список и порядок серверов,
порядок выбора, повторные проверки, интервал, тест при подключении, таймаут,
HTTP-статус, удержание, подтверждения, срок годности результата, цепочка группы
(профиль-источник) и разрешение мобильной сети.
URL-test дополнительно показывает GET/HEAD и запросы на сервер; Speedtest —
длительность загрузки и лимит трафика. Все пункты доступны до ввода серверов.

Выберите «Тип: список серверов» и вставляйте ссылки подряд, по одной строке.
Пустая строка завершает список; 0 отменяет ввод. Нужно от 2 до 1000 разных участников
одного семейства; общий лимит — 1000 профилей пользователя. Повторная ссылка не
создаёт дубликат. Сохранённые профили доступны через @номер, все показанные — через *.
Ссылки, их параметры и стабильные идентификаторы существующих профилей сохраняются.

Выберите профиль-источник из участников: контракт rc11 требует его при сохранении.
Вариант «Не задана» обозначает незаполненное поле и не передаётся клиенту.
[0] проверяет форму и переводит к подтверждению сохранения; [99] отменяет правки.
Неполная группа остаётся в форме, без ложного сообщения об успешном сохранении.

Для адреса Speedtest предлагаются Cloudflare 1 МиБ и 10 МиБ, а также свой HTTPS URL.
При редактировании можно оставить текущий адрес. Выбор размера ответа не изменяет
лимит трафика или длительность. Для новой группы исходные настройки сервера сохранены:
повторные проверки и мобильная сеть выключены, тест при подключении включён только
для URL-test. Скриншоты приложения не используются как основание менять эти значения.
Сервер ничего не измеряет: тест выполняет клиент после подключения.
Адрес download API: [официальный проект Cloudflare](https://github.com/cloudflare/speedtest).
