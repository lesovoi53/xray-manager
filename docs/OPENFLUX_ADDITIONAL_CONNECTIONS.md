# Дополнительные подключения OpenFlux

В меню пользователя TUNA → OpenFlux пункт **[9]** добавляет импортированный
`openflux-bundle://v2/...` как отдельное подключение. Исходное подключение,
его имя, UUID, группы, ключи, режим и флаг публикации не меняются.
Новая запись включается в обычную подписку `/sub/<token>` отдельной строкой.
Группы внешнего сервера не смешиваются с группами исходного бандла.

**[10] Добавленные серверы** показывает список: включить, отключить,
показать ссылку или удалить выбранное дополнительное подключение.
Пункт [1] управляет только исходным подключением. Выключенное исходное
подключение не мешает публикации включённых дополнительных подключений.

Сохраняется полный входящий payload, включая `issuer_id`, `id`, `revision`,
имя, порядок групп, URL, кодеки и ключи. Повторный идентичный импорт ничего
не меняет и не увеличивает ревизию пользователя. Если тот же источник
(`issuer_id`, `id`) прислан с другими настройками, возвращается 409:
сначала требуется явно удалить прежнюю дополнительную запись. Импорт
с конфликтующим идентификатором исходного подключения также отклоняется.
Совпадение имени само по себе не означает совпадение подключения.

## Данные и API

Аддитивная таблица `user_openflux_imports` хранит отдельные записи пользователя.
Существующие таблицы `user_openflux_config`, `user_openflux_selection` и
`openflux_groups` при импорте не изменяются. Автоматического преобразования
старых импортов нет: по старому состоянию нельзя достоверно восстановить
ранее заменённое подключение.

- `POST /api/users/<id>/openflux/import`: прежние поля `uri`/`payload`,
  `commit`, `expected_state_token`; действие теперь всегда добавочное.
  Preview возвращает `incoming_config`; commit — дополнительную запись с `import_id`.
- `GET /api/users/<id>/openflux/imported`: список дополнительных записей и токен состояния.
- `POST /api/users/<id>/openflux/imported/<import_id>`: `action` равен
  `enable`, `disable` или `delete`; обязателен актуальный `expected_state_token`.
- Экспорт `/openflux/export` по-прежнему относится к исходному подключению.
  Ссылка дополнительного подключения доступна в [10] и поле `uri` его записи.

Все URI содержат секреты. API должен оставаться доступным только локально.
Запись выполняется одной транзакцией SQLite; ошибка не оставляет частично
добавленное подключение. Счётчики пользователя и ETag обычной подписки
учитывают дополнительные подключения.

Структурированные группы URL-test/Speedtest остаются отдельной настройкой:
для включения ссылки в такую группу используйте существующее действие
«Взять профили из подписки пользователя». Импорт не перестраивает эти группы.

WebDAV уже добавляет подключения к существующему списку. Для Snell, Mieru,
WDTT, CSQTT, DNS и дополнительных URI используется пункт **[2] Добавить новые
ссылки к существующим**. Явные действия замены и очистки сохраняют своё назначение.

## Проверки и откат

Регрессии находятся в `tests/test_openflux_additive.py` и `tests/test_export_import.py`:
сохранность исходного подключения, две строки в подписке, повтор без дубликата,
конфликт состояния, отказ БД с откатом, повторная инициализация схемы,
управление через реальное Bash-меню и HTTP.

Перед обновлением нужны копии двух программных файлов и SQLite backup БД.
Откат программных файлов не удаляет новую таблицу и импортированные записи,
но старая версия сервиса их не публикует. Не восстанавливайте старую БД поверх
пользовательских изменений, сделанных после резервного копирования.
