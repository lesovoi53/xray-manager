# X-Manager v2026.10.08.1

## Подписка после перезагрузки

В v2026.10.07.2 были исправлены права каталогов `service-control`, но родитель
`/run/x-manager` мог заново создаваться с правами `0700` при запуске проверки
здоровья с `UMask=0077`. В результате TUNA снова возвращала HTTP 500.

Теперь обе операции, создающие runtime-каталог, разрешают проход к известным
отметкам остановки; содержимое закрытых файлов остаётся закрытым. Исправление
существующих родительских каталогов включено в установку и обновление.
Проверяется также случай, когда проверка здоровья запускается первой после
очистки `/run`. Перезагрузка рабочего VPS в рамках проверки не выполнялась.

## Внешний watchdog при обслуживании

Активные `vpn-watchdog.timer` и `vpn-watchdog.service` временно останавливаются
после создания резервной копии: сначала таймер, затем служба. После успешного
обслуживания или успешного отката восстанавливаются только ранее активные
единицы, без изменения автозапуска. Изначально остановленные единицы не запускаются.

Состояние сохраняется в закрытом файле
`/var/lib/x-manager/maintenance-watchdog.json`. При незавершённом восстановлении
следующее обновление останавливается с понятной ошибкой; после проверки состояния
служб восстановление запускается командой:

```bash
bash /usr/local/share/x-manager/distribution/install.sh --recover-watchdog
```

Для этого нужна версия установщика из этого выпуска. Если сбой произошёл до её
установки, используйте `install.sh` из распакованного архива v2026.10.08.1.
Ошибка остановки или восстановления watchdog не скрывается. Чужие изменения
автозапуска и явные отметки stop/off не отменяются автоматически.

Распаковка полного выпуска явно использует безопасный фильтр `tarfile`, если он
поддерживается Python; это устраняет предупреждение о смене поведения Python 3.14.
Локальный закрытый архив отката сохраняет исходные метаданные и администраторские
символические ссылки с явно выбранным режимом восстановления.

## Установка и границы

Проверки: 311 основных тестов и 98 тестов подписок в изолированной Debian 12;
четыре сценария паузы/восстановления на настоящем systemd Debian 13 для тестовых
службы и таймера. Проверки архива выполнялись с предупреждениями Python как ошибками.

Обновление: «Обновление и восстановление → Обновить полный выпуск». Для возврата
к предыдущему состоянию выберите резервную копию через меню восстановления.
Состав компонентов и их SHA-256 не менялись. Ключи, ссылки, UUID, порты и
настройки протоколов сохраняются.

На сервере 89 исправлена выдача TUNA без перезапуска служб: обычная подписка,
контейнер групп и публичная подписка ответили HTTP 200. Полное обновление этого
выпуска на рабочем VPS автоматически не выполнялось.
