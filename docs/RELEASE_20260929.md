# X-Manager v2026.09.29.1 — Волга, cookies и ограниченные перезапуски

Серверный выпуск для **Debian 12 и 13, amd64, systemd**. Обновлены OpenFlux, его интеграция, TUNA и документация. Версии Snell, Mieru, WebDAV и DNS-компонентов сохранены; неизменённые release assets проверены по прежним SHA-256.

## Изменения и причины

| Проблема | Решение |
|---|---|
| Волга отсутствовала в допустимых каналах и bundle v2 | `vyandex` добавлен в меню, runner, валидацию и импорт каталога |
| Истечение relay-авторизации приводило к 401 и потере передачи | Согласованное обновление HTTP/WS-авторизации, ограниченный retry, обновление при переподключении |
| OnlyOffice и SmartCaptcha воспринимались как готовый документ | Preflight различает редактор и проверяет auth/WS до изменения канала |
| Cookies требовали ручного копирования и могли неверно теряться при expiry=0 | Файл Netscape, корректные сессионные cookies, серверный refresh и таймер; ручная captcha остаётся ручной |
| Требовалось направлять через Xray оба вида трафика | Явный SOCKS5 CONNECT + UDP ASSOCIATE, без скрытого Direct при отказе |
| Службы могли перезапускаться бесконечно | Настраиваемая политика systemd с лимитом и явным сбросом через TUNA Watchdog |
| Предпросмотр показывал classic/0 вместо реального multistream bundle | Чтение метаданных из вложенного `payload` export API |
| Новое скачивание могло потерять тестовые серверные доработки | Полный закреплённый Release, checker и помощники включены в установку и snapshot/rollback |

Существующие форматы подписок, кодеки и ключи не заменены. Включение Волги не импортирует все группы всем пользователям: выбор состава bundle остаётся индивидуальным. Новые политики watchdog и cookies-таймер включаются пользователем; установка сохраняет уже существующие настройки.

Также удалён прежний жёстко заданный запасной пароль WDTT. При отсутствии `/etc/wdtt/main.password` выдача ссылки сообщает ошибку вместо подстановки чужого значения; существующий файл не меняется. Из теста удалён совпадавший пример. Это не стирает прежнюю историю Git и не заменяет отдельно согласованную смену ранее опубликованного секрета.

## Получение проверенного дистрибутива

На целевом Debian нужны root, `curl`, `tar`, Python 3 и работающий systemd. Полный установщик проверяет остальные зависимости. Сначала скачайте конкретный выпуск в отдельный каталог:

```bash
set -e
work=$(mktemp -d)
cd "$work"
base=https://github.com/lesovoi53/xray-manager/releases/download/v2026.09.29.1
curl -fL --proto '=https' --proto-redir '=https' "$base/x-manager.tar.gz" -o x-manager.tar.gz
curl -fL --proto '=https' --proto-redir '=https' "$base/SHA256SUMS" -o SHA256SUMS
awk '$2 == "x-manager.tar.gz" {print}' SHA256SUMS > distribution.sha256
test "$(wc -l < distribution.sha256)" -eq 1
sha256sum -c distribution.sha256
mkdir source
tar -xzf x-manager.tar.gz -C source
cd source
```

SHA-256 проверяет соответствие файлу выпуска, но не является независимой подписью издателя. Не выполняйте непроверенный архив или смесь отдельных файлов с разных веток.

### Новая установка

Без Xray, с явно выбранным прямым выходом:

```bash
bash install.sh --direct
```

При подготовленных совместимых Xray-шлюзах:

```bash
bash install.sh --quick
```

Для интерактивного выбора компонентов — `bash install.sh --manual`. Установщик не заменяет независимый Xray. Для standalone он проверяет доступные шлюзы; адаптер поддерживаемой базы панели — отдельный путь интеграции. 443 и 8443 не выбираются для новых слушателей.

### Обновление

Из уже скачанного и проверенного дистрибутива:

```bash
bash install.sh --update
```

Либо штатный пункт полного обновления в `x-manager`, когда установлен обычный выпускной updater. Обновление перезапускает затронутые работающие службы и может прервать соединения. Ранее остановленные службы не должны запускаться автоматически.

Для ранней preview-установки Волги используйте **полный дистрибутив и команду выше**: старый updater может блокировать обновление по `volga-preview.lock`. Новый установщик снимает этот маркер после успешной установки. Не удаляйте защиту вручную и не скачивайте по одному `bin/x-manager` без остальных файлов.

После обновления:

```bash
x-manager
systemctl status tuna-subscriptions --no-pager
systemctl status openflux@N --no-pager
```

Проверяйте только настроенные каналы вместо буквального `N`. Затем проверьте свою подписку без публикации токена и реальные TCP/UDP назначения с совместимого клиента. Для настройки Волги и cookies используйте [руководство](VOLGA_SERVER.md).

### Откат

Сохраните строку `Backup:` из вывода установщика. Он печатает готовую команду:

```bash
bash /usr/local/share/x-manager/distribution/install.sh --rollback /var/backups/x-manager-XXXXXXXX
```

Подставьте **свою** копию. Откат восстанавливает управляемые файлы, SQLite, iptables и состояния служб на момент снимка. Более поздние изменения этих данных будут заменены. Пакеты APT и системные пользователи сохраняются. При неудаче автоматического отката не удаляйте снимок — сначала проверьте сообщение и службы.

Чистая установка именно этого полного выпуска на Debian 12 с systemd отдельно не повторялась; там выполнены тесты и проверки core, указанные выше.

## Ограничения и дальнейшая работа

- Ошибка создания TUN/hev-socks5-tunnel в текущем TUNA-клиенте требует отдельного исправления клиентским агентом. Успешный серверный тест не доказывает её устранение.
- SmartCaptcha может снова потребовать ручного действия с IP VPS; таймер не решает captcha и не гарантирует вечные cookies.
- Новый Windows-помощник проверен синтаксически; его интерактивный сценарий требует отдельной приёмки.
- Watchdog контролирует аварийный выход процесса, не зависание и не доступность конечных сайтов.
- Нельзя переносить результат теста Волги на все протоколы, ОС, архитектуры и версии клиентов.
