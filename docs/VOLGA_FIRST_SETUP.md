# Первоначальная настройка Волги и cookies

Если проверка документа требует SmartCaptcha, рабочий канал не изменяется. Валидные введённые ссылки сохраняются в закрытом черновике `/etc/openflux/volga-drafts/<classic|multistream>/<1–8>.urls`. Каталоги имеют права 0750, файлы — 0640, владелец root, группа openflux. Classic и Multi-Stream имеют отдельные черновики.

1. В «Каналы» выберите канал и введите ссылки. При отказе авторизации они сохранятся как черновик.
2. Откройте «Настройки → Cookies Яндекс Волги». Здесь показаны номера черновиков и количество документов.
3. Выберите [1] «Получить и проверить cookies сейчас». Если настроенных каналов Волги нет, служба проверит документы из черновиков текущего режима. При наличии настроенных каналов автоматическое обновление продолжает проверять их; заброшенные черновики не мешают рабочим каналам.
4. Если требуется ручная SmartCaptcha, используйте [6] — инструкцию по браузеру через SSH-туннель этого VPS и передаче cookies. Импорт готового файла доступен через [5]. Скрипт не решает капчу автоматически.
5. Выберите [7] «Продолжить настройку из черновика», затем номер канала. Авторизация будет проверена повторно. Только после успеха конфигурация применяется и запускается выбранный канал. После устойчивого запуска его черновик удаляется. Кодек и ключ шифрования сохраняются.

[8] удаляет только выбранный черновик текущего режима, без изменения рабочего канала. Для Classic с одной ссылкой и Multi-Stream с несколькими нужно возобновлять настройку в соответствующем режиме.

Пункт [6] «Одна команда для Windows: браузер и cookies» выводит одну готовую строку PowerShell с адресом и портом текущего SSH-подключения. Строка скачивает актуальный помощник в `%USERPROFILE%\VolgaCookies` и запускает его; при неудачном скачивании старый файл не запускается. Команду можно выполнять из `C:\Windows`, права администратора не нужны. При запуске меню вне SSH вместо адреса/порта могут быть показаны SERVER_IP/SSH_PORT: их нужно заменить своими значениями.

Windows-помощник сам открывает отдельное SSH-окно для ввода пароля, выбирает свободный локальный порт, проверяет ответ SOCKS5 и HTTPS через VPS, затем запускает отдельный Chrome и проверяет готовность браузера. Ручной запуск туннеля не требуется. Перед экспортом проверяется открытие вкладки редактора docs.yandex.ru; преждевременный Enter не закрывает туннель. При ошибке передачи/проверки предлагается повторить попытку (R), сохраняя окно и туннель, либо завершить (Q). После открытия документа и ручного подтверждения помощник передаёт только cookies Яндекса, запускает `volga-cookies.service` для проверки и закрывает только свой туннель при успешном завершении или отмене. Для отдельных операций SSH пароль может запрашиваться повторно. Обычные окна Chrome не затрагиваются; отдельный профиль помощника следует удалить вручную после закрытия этого окна.

При неудачной проверке канала рабочая конфигурация не изменяется. Автоматическое обновление заменяет cookies только после проверки документов. Явный импорт файла cookies — отдельное действие: он сохраняет резервную копию прежнего файла, устанавливает импортированный и затем помощник запускает проверку на VPS; неудача этой проверки не означает автоматического возврата к прежним cookies. При отказе запуска канала применяется существующий механизм резервного копирования и восстановления конфигурации, а черновик остаётся для повторной попытки. Неизвестная ошибка проверяющей программы сохраняется в `/etc/openflux/volga-check-error.txt` с правами 0600; файл может содержать приватные адреса, его не следует публиковать целиком.

Изменение входит в исходные файлы `scripts/openflux-volga.py` и `bin/x-manager`. Установщик уже копирует оба файла, сохраняет полный дистрибутив и включает `/etc/openflux` в резервное копирование; отдельная миграция рабочих каналов не нужна. Новая публикация установочного архива выполняется после ручной приёмки, не автоматически вместе с локальной правкой.

Проверки перед публикацией: 18 тестов Волги и 3 теста навигации в изолированном Debian13; Windows PowerShell проверяет фактический SOCKS5 handshake, отказ закрытого порта/другого протокола, выбор свободного порта и запуск сформированной одной команды с подменёнными SSH-командами, включая отказ скачивания. На тестовом VPS отдельно проверены чтение черновика пользователем openflux и cookies из браузера после ручного открытия редактора. Это не автоматизированная проверка прохождения SmartCaptcha: она остаётся ручной.
