# v2026.09.29.2: обновление старой установки со шлюзами в шаблоне

Этот выпуск исправляет обновление X-Manager, когда SOCKS5 и REDIRECT сохранены в `xrayTemplateConfig` панели x-ui, а TPROXY — в таблице `inbounds`. Ранее установщик видел только табличные шлюзы, пытался добавить существующие порты повторно и завершался ошибкой конфликта. Удаление старого файла меню не устраняет эту причину.

## Изменения

- Общий модуль `scripts/xray_gateways.py` читает оба источника. План портов и миграция используют одинаковые правила.
- Сохраняются существующие порты, теги, настройки, клиенты и routing. Повторное обновление не создаёт дубликаты и не требует перезапуска панели, если миграция базы ничего не изменила.
- При нескольких подходящих шлюзах используется явно сохранённый/заданный порт. Противоречие конфигурации останавливает операцию. Автоматический выбор случайного шлюза исключён.
- SOCKS должен принимать IPv4 loopback, no-auth и UDP. TPROXY должен обслуживать TCP/UDP, REDIRECT — как минимум TCP. Неподходящий вход не изменяется автоматически.
- Старый `tuna-watchdog.timer` больше не может незаметно вмешаться в обновление. Если он активен/включён или работает его служба, обычная установка прекращается до установки пакетов и изменения управляемых файлов.
- Для перехода предусмотрен явный ключ `--migrate-legacy-watchdog`. После снимка останавливаются старый таймер и его служба; включённый автозапуск отключается. Старые файлы сохраняются.
- Работающим поддерживаемым службам задаются **3 повторные попытки с паузой 30 секунд**. Сама настройка политики их не перезапускает; дальнейшее обновление компонентов может перезапустить затронутые службы. Остановленные службы не включаются в миграцию политики.
- В allowlist watchdog добавлена `x-ui`. Снимок включает старые watchdog units/script и каталоги override всех поддерживаемых служб. При откате возвращаются прежние файлы, политики и состояние таймера.

Это не адаптер Remnawave: исправление относится к совместимой базе x-ui. Core, компонентные бинарники и source assets сохранены из v2026.09.29.1 без изменения хешей.

## Что произойдёт при запуске

Перед запуском проверьте свою ОС: только Debian 12/13 amd64, systemd. Если на сервере уже существуют рабочие 443/8443 у Xray, они остаются существующими входами; новые службы не получают эти порты.

Полный `--update` обновляет комплект и устанавливает отсутствующие TUNA/WebDAV. TUNA по стандартной схеме слушает loopback; WebDAV получает свободный разрешённый порт. OpenFlux без ссылок не запускается. Существующие пользователи, пароли, ключи, порты и режимы сохраняются. Отдельная установка Xray/WDTT/CSQTT не заменяется.

Команду выполняет владелец сервера вручную. Предварительное удаление X-Manager или конфигураций не требуется:

```bash
bash <<'UPDATE'
set -euo pipefail
work=$(mktemp -d)
cd "$work"
base=https://github.com/lesovoi53/xray-manager/releases/download/v2026.09.29.2
curl -fL --proto '=https' --proto-redir '=https' --connect-timeout 15 --max-time 300 --retry 2 "$base/x-manager.tar.gz" -o x-manager.tar.gz
curl -fL --proto '=https' --proto-redir '=https' --connect-timeout 15 --max-time 300 --retry 2 "$base/SHA256SUMS" -o SHA256SUMS
awk '$2 == "x-manager.tar.gz" {print}' SHA256SUMS > distribution.sha256
test "$(wc -l < distribution.sha256)" -eq 1
sha256sum -c distribution.sha256
mkdir source
tar -xzf x-manager.tar.gz -C source
bash source/install.sh --update --migrate-legacy-watchdog
UPDATE
```

SHA-256 сверяет файл с manifest релиза, это не независимая подпись издателя. Обновление может кратковременно прервать соединения. Сохраните вывод `Backup:` и напечатанную команду `Rollback:`.

## После установки

1. Откройте `x-manager`, проверьте прежние службы и реквизиты.
2. Главное меню → «Обновление и восстановление» → «TUNA Watchdog»: проверьте лимиты, при необходимости измените их для конкретной службы.
3. Убедитесь, что старый `tuna-watchdog.timer` остановлен/отключён. Новая реализация работает через политики systemd, отдельного активного демона watchdog не требует.
4. Проверьте реальные TCP и UDP через существующий Xray и отдельно клиентские подключения. Успех SOCKS handshake или статус active сами по себе этого не доказывают.

Новые, впервые установленные службы автоматически не получают политику миграции: она применяется к работавшим до обновления. Их можно настроить в меню. Лимит учитывает начальный запуск и последующие старты, включая ручные. После исчерпания нужен явный сброс; при перезагрузке счётчик systemd сбрасывается. Зависание процесса эта политика не обнаруживает.

Откат выполняется командой, напечатанной установщиком, например:

```bash
bash /usr/local/share/x-manager/distribution/install.sh --rollback /var/backups/x-manager-XXXXXXXX
```

Замените путь своей копией. Восстанавливаются данные на момент снимка, включая прежний watchdog. Пакеты APT и созданные системные пользователи не удаляются. Рабочие службы, конфигурации которых установщик не меняет, не требуют переустановки.

## Проверки

- Ошибка шаблонных шлюзов воспроизведена на искусственной SQLite-базе до исправления.
- Пять регрессионных тестов: сохранность и повтор, нестандартный порт, конфликт сохранённого порта, неоднозначность с явным выбором, отказ для несовместимого SOCKS без изменений базы.
- Debian 12 и 13: по **44 теста диспетчера и 79 тестов TUNA**, PASS.
- Изолированный Debian 13 с реальным systemd: блокировка обновления без ключа миграции, успешный переход, искусственная ошибка сразу после перехода с автоматическим восстановлением старого таймера и override, ручной откат — PASS.

- Чистая установка, повторное обновление, сохранение stopped/disabled состояния и HTTP-проверки TUNA/WebDAV в Debian 13 — PASS.

Это локальные проверки. На рабочем сервере выполнен только предшествующий аудит; данный выпуск там ещё не установлен. Окончательная проверка трафика и пользовательская приёмка следуют за ручным обновлением.
